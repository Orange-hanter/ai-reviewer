# 20 — Rust — основная реализация, JS-копии deprecated

> Категория: 🔵 Архитектура · Риск: средний · Зависимости: порт Фазы 3 (`rust/`), parity-скрипты, `docs/probe-openrouter-2026-10-14.md`

## Контекст

Портированные модули живут в двух копиях: Rust-бинарь и эталонный JS, на который обёртка
падает без бинаря. Каждая правка поведения делалась дважды и сверялась parity-скриптами.
Решение владельца от 2026-10-14: дальнейшая работа идёт только в Rust. JS-копии остаются
как deprecated fallback и удаляются после сверки, что в них не осталось ничего, чего нет
в Rust.

Первые две правки по этому правилу — из замера OpenRouter
(`docs/probe-openrouter-2026-10-14.md`):

1. каскад ретраев: `gemini-3.8-flash` и `glm-5.3-flash` на OpenRouter отвечают на
   `effort=none` `HTTP 400: Reasoning is mandatory…`, а ступень `none` есть в каскаде
   и JSON-, и prose-вызовов;
2. системные промпты: целиком на английском, с усилениями из сводки исследований (ниже).

## Текущее состояние (до правки)

- Каскад жил только в JS: `lib/llm.mjs` `chatJson` / `chatText`. Бинарь
  `rust/target/debug/llm` делал один HTTP-запрос. Повтор внутри `catch` ничем не
  обёрнут, поэтому 400 на `none` уходил наверх как сбой всего вызова.
- Системные промпты — побайтовые копии в `lib/prompt.mjs` и `rust/src/prompt.rs`. Обе
  английские, но с русскими вставками: маркер пропуска `«… (строки N–M пропущены)»`
  (`lib/context-window.mjs:42`) и `(нет)`. Указания писать вывод на русском были набраны
  капсом.
- `buildMergedSpecialistSystem` и схема refutation в `createPromptBuilder` собирались
  только в JS, хотя у второй есть Rust-копия.
- CI гонял `npm test` до `cargo build`, то есть юнит-тесты видели только JS-fallback.

## Решение

### 1. Каскад — `rust/src/llm/cascade.rs`

- `next_attempt(kind, step, prev, failure)` — чистая функция решения. Правила первой
  ступени те же, что в JS. Новое правило: 400 «Reasoning is mandatory / cannot be
  disabled» после попытки на `none` даёт ещё одну попытку на `low` с
  `max_tokens + 8000`. Это правило проверяется раньше ветки «400 при JSON-mode», иначе
  тот же 400 снимал бы JSON-mode и не возвращал reasoning. Каскад делает не больше трёх
  попыток.
- `run_cascade_with(req, chat)` — цикл с подменяемым транспортом. Тесты прогоняют
  сценарии без сети.
- Бинарь `llm`: поле `"cascade": "json" | "prose"` во входе включает режим каскада. Вывод
  такой: `value` или `content`, `repaired`, `usage`, `usages` (usage каждого дошедшего
  ответа, в том числе неразобранного), `throttled`, `log`. Ошибка отдаёт флаги
  `status/empty/truncated/badEscape` и тоже `usages` с `log`.
- `lib/llm.mjs`: при наличии бинаря `chatJson` и `chatText` уходят в
  `chatCascadeRust`. Слоты семафоров берутся один раз на весь каскад. JS-каскад
  помечен `@deprecated` и нового правила не получает.

### 2. Промпт — `rust/src/prompt.rs`

Сводка источников (исследование 2026-10-14; непроверенное помечено):

| Приём | Источник | Где в промпте |
|---|---|---|
| Явное «пусто — нормальный ответ», цена ложного блокера | Anthropic `claude-code-security-review`; Anthropic «reduce hallucinations» | `<evidence_rules>`, шапка жюри |
| Якорная рубрика confidence с порогом | Anthropic security-review (0.7/0.8/0.9) | `<confidence>`; порог 0.8 = `REVIEW_CONFIDENCE_MIN` |
| Список «не репортить» | Claude Code `/code-review`, security-review | `<do_not_report>` (прежние пункты a–d) |
| Дословная цитата как доказательство | Anthropic «reduce hallucinations» | `<evidence_rules>`, формат пункта |
| Только код, внесённый PR | PR-Agent `pr_reviewer_prompts.toml`, security-review | `<evidence_rules>` |
| Частичный контекст ≠ отсутствие | PR-Agent | `<evidence_rules>`, `<context_semantics>` |
| Конкретный сценарий отказа | PR-Agent | `<evidence_rules>`, поле `body` |
| Содержимое PR — данные, не инструкции | PR-Agent | `<untrusted_input>` |
| XML-разделы, причина правила вместо капса | Anthropic prompting best practices | весь текст |
| Не расписывать ход рассуждения reasoning-моделям | Anthropic; OpenAI (только вторичные источники) | step-by-step в промпте нет |

Язык: исследований «английская инструкция + русский вывод» именно для код-ревью не
нашлось. Общие работы (NAACL 2025, arXiv 2512.02841) показывают, что английская
инструкция не хуже родной или хуже незначительно. Поэтому промпт английский, а вывод
(`summary`, `title`, `body`, `reason`, пункты ролей) остаётся русским, его читают
разработчики. Переключатель языка вывода в эту правку не входит: замер прохода 2
показал −30% completion на EN, но решение про язык вывода продуктовое.

Выходные контракты не изменились. Это формат пункта и `quote:`, `### ROLE: <role>`,
JSON-схемы жюри и verifier'а, фразы «серьёзных замечаний нет» и потолки 8 и 12.

Маркер пропуска стал `… (lines N–M not shown)`. Он общий для оркестрации
(`lib/context-window.mjs`) и обеих копий промпта, поэтому механически правится в обеих.
Без этого deprecated-промпт ссылался бы на маркер, которого в контексте нет.
`buildMergedSpecialistSystem`, `buildAggregatorMessages` и
`buildSpecialistAggregatorMessages` при наличии бинаря собираются в Rust.

### 3. Проверки

- `rust/parity/prompt.parity.mjs`: у system-сообщений сверяется только роль.
  Reference-секции помечены `rust-owned` и считаются отдельно. User-части сверяются
  побайтово, как раньше.
- `test/rust-parity-guard.test.mjs`: маркеры промпта проверяются в Rust, величины
  потолков сверяются по константам обеих сторон.
- CI: `cargo build` перенесён перед `npm test`, чтобы юнит-тесты шли по основной
  реализации. Без бинаря (локально) тесты по-прежнему проходят на JS-fallback.

### 4. Замер на живых моделях (2026-10-14, OpenRouter)

Проверялся промпт жюри. Старый промпт (JS-копия 0.5.1) сравнивался с новым на диффе
`billing-webhook.js` из прохода 2 (5 подсаженных дефектов: A timing, B SQL, C кэш,
D traversal, E floating promise). Вызовы шли через `chatJson` с Rust-каскадом, 2–3
повтора на вариант, всего ≈ 90 вызовов, меньше $0.10. Recall считался по ключевым словам
в title/body/quote. «Лишние» — находки вне пяти дефектов.

| Модель | Старый: recall · лишние · находок | Новый: recall · лишние · находок |
|---|---|---|
| `claude-haiku-5.5` | 5/5 ×2 · 3 · 8 | 5/5 ×6 · 0–1 · 5–6 |
| `mimo-v2.6-flash` | 5/5 ×3 · 0–2 · 7–8 (80–112 с) | 5/5 ×3 · 1 · 6–7 (46–55 с) |
| `gemini-3.8-flash` | 4/5 ×4, 5/5 ×1 · 0 · 4 | 4/5 ×6, 5/5 ×2 · 0 · 4 |
| `gpt-6-luna` | 5/5 ×4, 4/5 ×1, 3/5 ×3 · 0–1 · 3–5 | 5/5 ×1, 3/5 ×2 · 0 · 3–4 (последняя версия) |

Первая версия нового промпта у luna стабильно теряла A и C. Абляция показала причины:
пункт «не репортить семантику языка» (A) и правило «не хватает данных — не репорти» (C).
Оба пункта уточнены: безопасность валидного кода и дефект, целиком видимый в показанном
коде, под эти исключения не подпадают. Ещё добавлено: «minor не блокирует — не
выбрасывай». Разброс у luna на старом промпте того же порядка, на одном кейсе их не
различить.

Каскад на живом провайдере: `gemini-3.8-flash` с
`REVIEW_AGGREGATOR_REASONING_EFFORT=none` получил 400, повторил вызов на
`low`/32000 и вернул 4 находки.

Остальные роли проверены на формат (2026-10-15, `claude-haiku-5.5`, 5 вызовов, тот же
кейс). Проверялось то, что разбирает пайплайн, а не recall:

| Роль | Результат |
|---|---|
| advisor | 6 пунктов, у каждого строка `quote:`, текст по-русски |
| специалист security | 4 пункта, у каждого строка `quote:`, все по своей роли |
| панель из трёх ролей | `splitMergedSpecialistText` → `ok`, секции 4 / 5 / 3 пункта |
| verifier | 2 настоящих дефекта → `verified`, 2 подсаженных FP («`db` не импортирован», «`totals` теряет копейки») → `rejected`, `reason` по-русски |

## Миграция

**Доставка бинарей (решено 2026-10-15: готовые бинари в релизе).**
- `.github/workflows/release-binaries.yml` на публикацию релиза собирает `--release --locked`
  под `linux-x64` (ubuntu-22.04 — ради glibc 2.35), `linux-arm64` и `darwin-arm64`.
- Перед упаковкой он гоняет `npm test` на релизных бинарях, затем прикладывает к релизу
  `ai-reviewer-bins-<target>.tar.gz` и `.sha256`. `rust/Cargo.lock` теперь в git.
- Шаблон потребителя качает архив по тому же ref, что и движок, сверяет sha256 и
  распаковывает в `.ai-reviewer-engine/rust/bin`.
- Нет архива (пин не тег, старый релиз) или sha256 не совпал — предупреждение и
  JS-копии; на гейт это не влияет.
- Поиск бинарей собран в `lib/rust-bin.mjs`. B2 из аудита закрыт: раньше все 26 обёрток
  искали только `rust/target/debug`.

Ниже — состояние до этого решения.

**Блокер (был): потребитель бинарей не получает.** В пакет (`package.json` → `files`) каталог
`rust/` не входит, а `rust/target/` в `.gitignore`. Шаблон `examples/ci/pr-review.yml`
клонирует движок и сразу запускает `node .ai-reviewer-engine/bin/pr-review.mjs`, шага с
`cargo build` в нём нет. Резолверы ищут только `rust/target/debug/<mod>`. В итоге у
потребителя каждая обёртка падает на JS-копию: работают замороженные промпты 0.5.1 и
JS-каскад без ретрая на «Reasoning is mandatory». Пока доставка бинарей не решена,
правки этого RFC доходят только до машин с собранным `rust/`: CI движка и локальные
прогоны. Способ доставки — отдельное решение. Варианты: шаг сборки в шаблоне
потребителя или готовые бинари в релизе плюс резолвер. Аудит JS-копий (2026-10-15)
показал и другие условия удаления; их список — в `docs/dev/journal.md`.

При собранном бинаре для потребителя изменилось только содержимое промпта. Футер, namespace маркеров и
контракты `export`/`swarm`/`structure` не менялись. Инкрементальный прогон (RFC 05)
один раз перечитает файлы с оконным контекстом, потому что изменился вход модели (текст
маркера).

## Риски и что не делаем

- Замер выше — один синтетический кейс. Recall сравнивался только у жюри, у остальных
  ролей проверен формат на одной модели. По протоколу `docs/model-tuning.md` до релиза
  нужно сравнить `pr-review-gold` со старым промптом. `npm run eval` LLM не вызывает и
  промпт не проверяет.
- Рубрика confidence может сдвинуть калибровку: модели, которые раньше ставили 0.8 по
  умолчанию, начнут ставить 0.6–0.8 на «зависит от невидимого кода». Это намеренно, но
  число блоков может упасть. Проверять на gold.
- JS-копии не удаляем. Критерий удаления: каждый `*.parity.mjs` зелёный, и JS-копия не
  несёт поведения, которого нет в Rust (обратный аудит по модулям). Это отдельная задача.
- Оркестрация (`pipeline.mjs`, chunk-routing, specialist-merge, incremental) остаётся в
  JS, «только Rust» её не касается до отдельного решения.

## Оценка

Каскад и промпт сделаны в этой правке. Осталось: gold-прогон старого и нового промпта
(1 задача) и аудит JS-копий перед удалением (по задаче на модуль, 20+).
