# Changelog

## Unreleased

**Для потребителя — что меняется при обновлении пина с `v0.6.4`:**

- **Blast-radius находит больше вызовов вне PR — и при `REVIEW_BLAST_VERIFY=0`.** Одноимённые
  функции в разных модулях (`update_status` в четырёх сервисах) раньше давали «символ не
  разрешён»; теперь узел выбирается по файлу PR. Файл, зависящий от двух изменённых символов,
  даёт находку на каждый, а не на первый. В `moa` при `0` такие находки, как и прежде,
  понижаются до minor и merge не блокируют; в `consensus` их больше доходит до verifier'а.
- Формат футера sticky, namespace маркеров, контракты `swarm` / `export` / `structure` — без
  изменений.

### Исправлено — проверка blast-находок по итогам замера ([RFC 21](proposals/21-blast-verification.md), раздел «Замер»)

Shadow-замер на gold-private (20 clean-кейсов и 2 кейса «PR сломал вызов вне PR») нашёл три
причины, по которым поломка проходила мимо:
- строка из графа — место ребра (бывает строкой импорта), а не вызова, и окно verifier'а
  вставало мимо вызова: находка переносится на ближайший вызов символа (`blastGraphLine` —
  прежняя строка);
- омонимы не разрешались (см. выше);
- одна находка на файл: verifier судил контракт чужого символа.

Итог: ложных blast-блоков 0 на 136 вердиктах clean-набора; поломка cod-doc (`update_status`)
поймана, Orakul (`getTgToken` через `import * as`) — нет: такого ребра нет в графе Graphify
(BLV-009). Дефолт `REVIEW_BLAST_VERIFY` остаётся `0`.

Для замера: `REVIEW_GOLD_BLAST=1` — настоящий blast-radius в gold-раннере; режим `--blast`
сборщика `pr-review-gold-harvest-local`; событие наблюдаемости `verifier_blast_verdicts`.

### Добавлено — blast-radius видит вызов через namespace-импорт (BLV-009)

Graphify не связывает `m.S()` при `import * as m from './A'` / `const m = require('./A')` с
функцией `S` в JS/TS. Движок теперь сам находит такие вызовы: импортёры файла символа — по
рёбрам `imports` графа, в каждом — алиас и строки `m.S(` (confidence `EXTRACTED`). Python не
затронут — там граф справляется. На gold поймана вторая настоящая поломка (Orakul `getTgToken`
→ `server.js:90`): 2 из 2. Тот же прогон нашёл класс ложных блоков — переименование `.jsx` →
`.tsx` при резолвере сборки (BLV-010), поэтому дефолт `REVIEW_BLAST_VERIFY` остаётся `0`.

### Исправлено — blast-находка судит контракт в месте использования (BLV-010)

Находка переносится на вызов `S(` / `m.S(` или JSX-тег `<S` (React-компонент); если символ в
файле только импортирован — `minor` без verifier'а: на строке импорта несовместимость контракта
не проявляется. Verifier'у добавлено правило: разрешение пути импорта решает конфиг сборки,
переименованный файл — не доказательство поломки. Clean-кейс с `.jsx` → `.tsx` — 0 ложных блоков
в трёх прогонах подряд (было 3); обе настоящие поломки по-прежнему ловятся.

## 0.6.4 — reviewSkip для сгенерированного, запасной verifier, проверка blast — 2026-10-21

Пин потребителя — `v0.6.4`. Новое для потребителя: `layout.reviewSkip` действует только с
`REVIEW_PROFILE_TRUSTED=1` и `REVIEW_BASE_REF` (SHA base или полный ref) — CI-шаблон
восстанавливает входы ревью из base; lockfile снова уходят моделям, к ним добавлена
детерминированная проверка реестров; `REVIEW_VERIFIER_FALLBACK_MODEL` (#60); проверка
blast-находок verifier'ом (RFC 21, #61). Формат футера sticky и контракты `swarm` /
`export` / `structure` с `v0.6.3` не менялись.

### Безопасность — вход доверенного профиля из base, fail-closed sgconfig, проверка lockfile

Доработка `layout.reviewSkip` (PR #62) по итогам security-ревью, три пункта:

- **Граница доверия** (`lib/trusted-input.mjs`). `REVIEW_PROFILE_TRUSTED=1` теперь требует
  `REVIEW_BASE_REF` — SHA коммита или полный ref `refs/remotes/…`/`refs/heads/…` (короткое
  `origin/main` отвергается: DWIM-резолв зависит от ref'ов checkout'а PR). Движок сам читает из base через git файл профиля,
  `repoRulesFile`, `AGENTS.md`/`agents.md` (каталог профиля и корень), `paths.fpPatterns`, а
  sgconfig ast-grep с его `ruleDirs`/`utilDirs` копирует из base во временный каталог и
  запускает ast-grep с копией. Файла нет в base — он отсутствует, копия из PR не
  подставляется. Без `REVIEW_BASE_REF`, с невалидным или нерезолвящимся ref доверие
  снимается (строка `REVIEW_PROFILE_TRUSTED=1 снят: …` в логе), `reviewSkip` не применяется.
  CI-шаблон восстанавливает из base профиль, `repoRulesFile`, `AGENTS.md`, fpPatterns и
  каталог sgconfig (пути — из профиля base) и передаёт `REVIEW_BASE_REF`.
- **`parseSgconfigDirs` fail-closed.** Строка, которую подмножество YAML не понимает (ключ в
  кавычках, `---`, `?`, флоу-маппинг, якорь/алиас, `<<`, вложение под незнакомым ключом,
  кавычки внутри значения), даёт null → защищается каталог конфига и любой YAML PR. Раньше
  такие строки пропускались, и `"ruleDirs":` уводил каталоги правил из-под защиты.
- **Встроенный skip — только source map** `*.{js,mjs,cjs,jsx,ts,tsx,css}.map` (голый
  `*.map` — nginx-карты, данные — уходит моделям и не инертен для `reviewSkip`). **Lockfile
  уходят моделям**, как до `reviewSkip`; скрыть их может только `reviewSkip` доверенного
  профиля. Маршрут PR не менялся (PR из одних lockfile — skip). Добавочно в npm/yarn/pnpm
  lockfile КАЖДОЕ значение добавленных строк (ключи yarn, `version`, `requires`, не только
  `resolved`) декодируется как у менеджера пакетов и классифицируется с начала значения или
  после `name@` (URL в середине, нераскодированная строка, управляющий символ — fail-closed):
  https вне `registry.npmjs.org`, `registry.yarnpkg.com` и env `REVIEW_LOCKFILE_REGISTRIES`,
  `http:`, иные схемы, git/`github:`-подобные спецификации, `file:`/`link:` вне репозитория, а
  fail-closed — обратный слэш, `%`, userinfo, порт, непарная кавычка — дают детерминированную
  находку major (prescan, `ruleId: lockfile-foreign-registry`). Она отменяет router skip/light.
  Пробел в этой проверке ничего не прячет: lockfile видят и модели.

**Для потребителя:** добавить в env шага ревью
`REVIEW_BASE_REF: ${{ github.event.pull_request.base.sha || format('refs/remotes/origin/{0}', github.base_ref || 'main') }}`
— без него `reviewSkip` перестанет применяться. Шаг «Take review profile from base branch»
обновить по шаблону. Частный реестр npm — в `REVIEW_LOCKFILE_REGISTRIES`.

### Добавлено — запасная модель verifier'а, `REVIEW_VERIFIER_FALLBACK_MODEL`

Раньше любой сбой основной модели verifier'а — сеть, лимит бесплатного тарифа, сорванный
JSON — давал «verifier недоступен» (RFC 18). При `REVIEW_LLM_REQUIRED=1` это degraded-блок
PR. Теперь тот же батч уходит запасной модели; в observability её вызов помечен `fallbackFrom`.

### Исправлено — лимит бесплатной модели больше не глушит весь ключ

Лимит `:free`-модели OpenRouter (`429 … free-models-per-day. Add 10 credits…`) считался
исчерпанием квоты ключа, и клиент отключал все вызовы прогона, включая платные. Теперь Rust
`quota_scope` различает лимит одной модели и квоту ключа: при лимите модели отключается
только она (RFC 20, § 7).
**Для потребителя — что меняется при обновлении пина с `v0.6.3`:**

- Ничего, пока не задана новая `REVIEW_BLAST_VERIFY` (дефолт `0` — прежнее поведение).
  Включение — `shadow`: blast-находки судит verifier, гейт их не блокирует, а пишет
  событие `blast_would_block`; это первый шаг к `1` (блок после `verified`).
- Артефакт экспорта — `EXPORT_VERSION` **3**: у находки появилось поле `wouldBlockBlast`,
  у статистики verifier'а — `bySource`. Аддитивно; потребитель, сверяющий версию на
  «известна ли», а не на равенство, ничего не замечает.
- Новое необязательное поле профиля `layout.reviewSkip` (действует при
  `REVIEW_PROFILE_TRUSTED=1`); без него меняется одно — source map JS/TS/CSS больше не
  уходят моделям в PR с кодом (ниже; lockfile — уходят, см. раздел «Безопасность» выше).
- Формат футера sticky, namespace маркеров, контракты `swarm` / `structure` — без изменений.

### Добавлено — проверка blast-находок verifier'ом ([RFC 21](proposals/21-blast-verification.md))

Разбор показал: в режиме `moa` (CI-шаблон) blast-находка до verifier'а не доходила —
strict-refutation понижал её до `minor` за отсутствие `advisorClaims`, которых у
детерминированной находки не бывает. Правило «blast блокирует после `verified`» было
недостижимо. Под `REVIEW_BLAST_VERIFY` (`0` | `shadow` | `1`):
- refutation пропускает blast-находку (`refutationStatus: not_applicable`, Rust-only);
- в отборе verifier'а она идёт после LLM-находок той же severity — граф не вытесняет из
  капа то, что согласовало жюри;
- verifier получает окно ±`REVIEW_BLAST_VERIFY_MARGIN` (20) вокруг строки вызова в файле
  вне PR и хунк, где меняется символ; файл не прочитан → `minor`, `unverified`;
- правило промпта `<blast_candidate_rule>`: `verified` только когда показанный код
  доказывает и смену контракта, и несовместимый вызов. Живая проверка на
  `deepseek-v4-pro`: смена сигнатуры → verified ×2, необязательный параметр → rejected ×2.

Дефолт переключится после замера на gold (план `blast-verification`, BLV-007/008).

### Сгенерированные файлы не уходят моделям — `layout.reviewSkip`

Класс skip роутера (lockfile, generated) решал только маршрут PR. Когда в PR рядом с ним был
код, skip-файл всё равно нарезался в чанки. Orakul коммитит 26k-строчный OpenAPI YAML и его
JSON-копии, которые CI сверяет с источником (`gen-openapi.mjs --check`). Жюри получало куски
YAML, читало отступы через границу чанка и на каждом прогоне поднимало блокирующий major
(«duplicate key», «description на неверном уровне»).

Теперь:
- файл, который роутер по имени считает generated (`x.generated.ts`, `dist/foo.js`), моделям
  уходит — маршрут PR по-прежнему считает его skip, но вход LLM по одному имени не сужается;
- trust gate: `reviewSkip` применяется только при `REVIEW_PROFILE_TRUSTED=1` (профиль взят
  из base-ветки; шаг — в `examples/ci/pr-review.yml`), без флага игнорируется со строкой в логе;
- встроенный skip сужает вход LLM только для source map JS/TS/CSS (после security-ревью;
  lockfile уходят моделям);
- allowlist инертных файлов (и для доверенного профиля): lockfile, `*.map`, `md`/`mdx`/`rst`,
  данные `json`/`yaml` — кроме dotfile, каталогов CI/IDE/инфраструктуры, инструкций агентам и
  конфигов сборки; код по расширению, `.github/`, пин движка `ai-reviewer-ref`, всё, что читает
  движок (профиль, `repoRulesFile`, `AGENTS.md`, каждое значение `paths.*`, путевые поля cfg,
  каталоги из `ruleDirs`/`utilDirs`/`testConfigs` sgconfig — fail-closed), и `layout.sensitive`
  не исключаются никогда; проигнорированные совпадения пишутся в лог;
- сужение диффа fail-closed: секции ключуются путём из `parseDiff`; путь PR без своей
  секции — модели получают полный дифф;
- новое поле профиля `layout.reviewSkip` (регекс или массив регексов) объявляет пути, которые
  никогда не уходят моделям. Роутер считает их skip (`routeDiff` получает `skipPaths`, паритетно
  в Rust), поэтому PR из одних таких путей — маршрут skip;
- находки моделей о skip-путях, их перенос из инкрементального state и prior findings в
  промпте отбрасываются; Δ-блок покажет такие находки снятыми;
- в sticky появляется строка «Не ревьюились моделями (generated/lockfile/reviewSkip профиля):
  N файл(ов)», в событии `plan` — `reviewSkipped: {builtIn, profile}`;
- prescan, blast-radius и карта PR skip-пути видят по-прежнему: меняется только вход LLM.

Reference-профиль Orakul (`profiles/orakul.json`, `examples/consumers/orakul/profile.json`)
объявляет `docs/08-technical/openapi/`, `app/server/apiDocs/openapi(.platform).json` и
`docs/dev/reference/api-endpoints-index.md`.

## 0.6.3 — Walkthrough отчёта не противоречит блоку — 2026-10-16

Пин потребителя — `v0.6.3`. Формат футера sticky, namespace маркеров, контракты `swarm` /
`export` (`EXPORT_VERSION` = 2) / `structure` с `v0.6.2` не менялись. Изменился вход модели
(промпт жюри), поэтому инкрементальный прогон один раз перечитает затронутые файлы.

### Исправлено — Walkthrough отчёта больше не противоречит блоку

Sticky мог писать «блокирующих дефектов не выявлено» при заблокированном merge. Причин две.
Жюри просили в `summary` «общий вердикт», и оно писало его до refutation, verifier'а и гейта.
А в Walkthrough всего PR шёл `summary` одного чанка, тогда как блок мог прийти из другого.
Теперь:
- `summary` жюри описывает, что меняет его часть, а вердикт выносит гейт (баннер блока);
- Walkthrough собирает до трёх разных описаний из кодовых чанков (`pickAggregateSummary`).

Живая проверка (haiku, тест с 5 дефектами + 2 куска Orakul #603, по 2 прогона): вердикт в
`summary` — 5 из 6 на старом промпте, 0 из 6 на новом.

### Blast-radius — текст находки читается без знания Graphify

Заголовок `Breaking change: caller вне диффа не обновлён` утверждал поломку, которую
blast-radius не проверяет, и был одинаков у всех находок. Теперь в заголовке символ
(`Код вне PR зависит от \`canWriteType\` — проверьте совместимость`), в теле — вид связи
(вызывает/импортирует), причина словами вместо `community` и `[EXTRACTED]`, и что делать.
Путь файла и caller-узел с именем файла (`AccessPanel.tsx`) в теле больше не повторяются —
позиция уже стоит рядом. Смена заголовка один раз покажет эти находки в Δ-блоке как
снятые и новые: ключ находки включает заголовок.

## 0.6.2 — настройки каждой модели, verifier без ложных отказов, учёт пустых ответов — 2026-10-16

Пин потребителя — `v0.6.2`. Формат футера sticky, namespace маркеров, контракты `swarm` /
`export` (`EXPORT_VERSION` = 2) / `structure` с `v0.6.1` не менялись. Новое для
потребителя — `LLM_MODEL_SETTINGS` (настройки каждой модели, `docs/configuration.md`). Без
неё поведение прежнее. Изменился вход модели: промпт verifier'а и specialist'а
architecture. Поэтому инкрементальный прогон один раз перечитает затронутые файлы.

### Релиз — таймерные тесты не срывают сборку бинарей

На `v0.6.1` сборка linux-arm64 упала на `cursor-plugin`: handshake MCP занял 6.8 с при
пороге 5 с, сразу после `cargo build --release`. Порог проверяет CI-раннер, а не бинари.
Теперь пороги латентности в тестах умножаются на `AI_REVIEWER_TEST_TIMING_SLACK` (по
умолчанию 1, `test/helpers/timing.mjs`). Дымовой `npm test` релиза запускается с
множителем `3`. Тесты при этом не выключаются: зависание по-прежнему ловится.
### Добавлено — `LLM_MODEL_SETTINGS`: настройки каждой модели отдельно

JSON `{"<модель>": {"effort", "jsonEffort", "maxTokens", "provider"}}`. Модели ведут себя
по-разному при одних параметрах:
- deepseek-v4.1-flash, nemotron и ling на `effort=low` тратят весь бюджет на рассуждение и
  отдают пустой ответ, а с `none` отвечают за секунды и в 10–30 раз дешевле;
- glm-5.3-flash без рассуждения отвечает 400.

Глобальный `REVIEW_REASONING_EFFORT` такие модели в одном ростере не совмещает. `provider`
уходит в запрос OpenRouter как есть (`order`, `ignore`, `quantizations`…). Ошибки разбора
пишутся в лог и не роняют прогон. Работает только с Rust-бинарём (RFC 20, § 6).

### Исправлено — verifier отклонял настоящую SQL-инъекцию «за непоказанные вызовы»

Правило промпта verifier'а «отклоняй, если доказательство зависит от непоказанного кода»
теперь касается только утверждений об этом коде: «отсутствует», «не определено», «не
вызывается». Дефект внутри показанного кода (SQL из строк, непроверенный путь, сравнение
секрета не за постоянное время) доказывается этим кодом. В сквозных прогонах SQL-инъекция
блокировалась в 2 из 6 случаев, после правки — в 12 из 12.

### Изменено — шире зона specialist'а architecture

Добавлены состояние без ограниченного времени жизни, ресурсы без жизненного цикла,
ввод-вывод в чистом слое и при импорте, асинхронная работа без владельца, контракт
(возвращаемая форма, ошибки, права), а не только сигнатура.

### Исправлено — пустой ответ модели теперь в учёте цены, причина видна в логе

Модель, которая на `effort=low` тратит весь `max_tokens` на рассуждение, возвращает пустой
content, но провайдер выставляет счёт за эти токены. Раньше usage такого ответа терялся.
Теперь он попадает в учёт цены (`costTracker`, `onUsage`), а в строке лога «content пуст на
effort=low» видны `finish` и длина рассуждения.

Повтор на `none` остаётся. Замер на чанке 49 КБ показал, что больший бюджет не спасает:
`deepseek-v4.1-flash` съел и 14000 токенов (RFC 20, § 5).

## 0.6.1 — исчерпанная квота провайдера LLM, шаблон без gh на раннере — 2026-10-16

Пин потребителя — `v0.6.1`. Формат футера sticky, namespace маркеров, контракты `swarm` /
`export` (`EXPORT_VERSION` = 2) / `structure` с `v0.6.0` не менялись. Если `pr-review.yml`
скопирован из шаблона 0.6.0, перенесите обновлённый шаг `Download engine binaries`. Новый шаг
сам берёт пиненный `gh`, если его нет на раннере. Без этого self-hosted раннер без `gh`
остаётся на JS-копиях.

### Шаблон CI — бинари ставятся и без `gh` на раннере

Self-hosted раннер без `gh` раньше получал предупреждение и оставался на JS-копиях. Теперь
шаг сам скачивает `gh 2.102.0` из релиза `cli/cli` и сверяет его по sha256, зашитому в
шаблон. Новый CI-джоб `consumer-binaries` исполняет шаг шаблона как есть против последнего
релиза, с `gh` и без него.

### Исправлено — исчерпанная квота провайдера больше не выдаётся за rate limit

Раньше недельный лимит Ollama Cloud (`429 … weekly usage limit`) считался обычным rate
limit. Движок ретраил с backoff, резал параллелизм и в sticky советовал «перезапустите job
позже», хотя перезапуск квоту не вернёт. Теперь:

- Rust `chat()` (`is_quota_exhausted`) распознаёт квоту: это 402 (у OpenRouter
  кончились кредиты или лимит ключа) и 429, в теле которого есть «usage limit», «quota»
  или «credits». Такая ошибка не ретраится и не режет семафоры. Каскад после неё не
  продолжает.
- После первой такой ошибки остальные вызовы клиента отказывают сразу, без сети: ключ у
  всех моделей один. Раньше прогон тратил тайм-бюджет на десятки заведомо пустых запросов.
- В sticky: метка «квота провайдера исчерпана» и совет пополнить квоту или сменить
  `LLM_API_KEY`/`LLM_BASE_URL`. Различает только Rust-отчёт, deprecated JS-копия пишет
  прежний совет.

## 0.6.0 — Rust как основная реализация, готовые бинари, английские промпты — 2026-10-15

Пин потребителя — `v0.6.0`, обязательно тег, а не SHA: Rust-бинари качаются из релиза по
имени тега. Чтобы новое поведение доехало, потребителю нужно перенести в свой
`pr-review.yml` шаг `Download engine binaries` из `examples/ci/pr-review.yml`. Без него
движок работает как раньше, на JS-копиях. Формат футера sticky, namespace маркеров и
контракты `swarm` / `export` (`EXPORT_VERSION` = 2) / `structure` с `v0.5.1` не
менялись. Вход модели изменился (промпт, маркер пропуска), поэтому инкрементальный прогон
один раз перечитает файлы с оконным контекстом.

### Rust — основная реализация, JS-копии deprecated (RFC 20)

Новые правки поведения идут только в Rust. JS-копии портированных модулей остаются
fallback'ом без бинаря и удаляются после аудита, что в них не осталось ничего, чего нет в
Rust. CI собирает Rust до `npm test`, поэтому юнит-тесты идут по основной реализации.

### Готовые Rust-бинари для потребителя

До сих пор потребитель Rust не собирал. Каталога `rust/` нет в пакете, в шаблоне CI нет
`cargo build`, поэтому у потребителя всегда работали JS-копии.

- Workflow `release-binaries` при публикации релиза прикладывает к нему архивы
  `ai-reviewer-bins-<target>.tar.gz` и `.sha256`. Платформы: `linux-x64`, `linux-arm64`,
  `darwin-arm64`.
- Шаблон `examples/ci/pr-review.yml` получил шаг `Download engine binaries`. Шаг качает
  архив по тому же ref, что и движок, сверяет sha256 и build provenance (`gh attestation
  verify --signer-workflow …/release-binaries.yml`), затем распаковывает в `rust/bin`.
  Нет архива или `gh`, не прошла любая проверка — бинари не ставятся, движок работает на
  JS-копиях.
- Обёртки ищут бинари через `lib/rust-bin.mjs`: `AI_REVIEWER_RUST_BIN_DIR` →
  `rust/target/debug` → `rust/target/release` → `rust/bin`.
- `rust/Cargo.lock` теперь в репозитории.
- **Потребителю:** обновить свою копию шаблона (новый шаг) и пинить тег, а не SHA: архив
  ищется по имени релиза.

### Каскад ретраев — в Rust, ретрай на «Reasoning is mandatory»

Каскад `chatJson`/`chatText` переехал в бинарь `llm` (`rust/src/llm/cascade.rs`, поле
`cascade` во входе). Новое правило: если после попытки на `effort=none` провайдер ответил
`400 Reasoning is mandatory`, каскад повторяет вызов на `low` с `max_tokens + 8000`. Раньше
этот 400 валил вызов целиком у моделей с обязательным reasoning (`gemini-3.8-flash`,
`glm-5.3-flash` на OpenRouter, `docs/probe-openrouter-2026-10-14.md`). Usage неразобранных
ответов по-прежнему учитывается.

### Системные промпты — английские, с рубриками

Системные промпты advisor'а, специалистов, панели специалистов, жюри и verifier'а переписаны
в `rust/src/prompt.rs`. Изменения:

- разделы в XML-тегах;
- рубрики severity и confidence с якорями (0.8 — порог блока);
- раздел «не репортить»;
- требование конкретного сценария отказа;
- содержимое PR явно объявлено данными, а не инструкциями;
- указания сформулированы без капса.

Вывод по-прежнему на русском, выходные контракты не изменились. Маркер пропуска в
контексте стал `… (lines N–M not shown)`. Gold-прогон нового промпта ещё не сделан
(RFC 20, «Риски»); A/B жюри на одном синтетическом кейсе — RFC 20, § 4.

## 0.5.1 — исправление безопасности роутера и разбора диффа — 2026-10-13

Первый опубликованный тег после `v0.4.0`: тег `v0.5.0` не создавался, поэтому всё из
секции 0.5.0 ниже потребитель получает с этим релизом. Формат футера sticky, namespace
маркеров, контракты `swarm` / `export` (`EXPORT_VERSION` = 2) / `structure` с `v0.4.0` не
менялись. Пин потребителя — `v0.5.1`.

### Безопасность — строка кода автора PR выключала ревью

Строки диффа делятся только по `\n`. С флагом `/m` JS считал началом строки ещё `\r`,
U+2028 и U+2029, а их автор PR кладёт внутрь своей строки кода. Так
`+код\u2028similarity index 100%` выдавал правку за чистый rename: файл уходил в `skip`,
и PR из одного такого файла не ревьюился вовсе (`lib/router.mjs`). Поддельный
`deleted file mode` выключал prescan на настоящем файле — обход `blockRules` (RFC 17,
`collectDeletedPaths`). Уязвим JS-путь, то есть потребитель без собранного Rust-бинаря;
Rust-ядро делит по `\n` и уязвимо не было.

### Исправлено — ложные «caller вне диффа» на путях с `_`

`emitBlastRadiusFindings` разбирает пути из текста blast-блока, а `formatBlastBlock`
пишет его для Markdown: `_` → `ˍ` (U+02CD). Путь `cod_doc/x.py` из блока не совпадал
с путём диффа, и каждый caller в файле с подчёркиванием выходил находкой «Breaking
change: caller вне диффа не обновлён» — на cod-doc PR #195 все 8 таких находок были
про файлы самого диффа. Тот же разбор терял confidence и `cross-community` у рёбер с
`_` в relation (`imports_from`). `parseBlastDependents` возвращает обратимую часть
экранирования (`ˍ`→`_`, `∗`→`*`); путь в находке теперь настоящий, и inline-комментарий
встаёт на файл. Получают исправленные пути и cue-факты (`lib/cues.mjs`).

### Исправлено — blast-radius пуст на Python-репозиториях

`extractChangedSymbols` / `collectBlastSymbols` узнавали только JS/TS-экспорты, а добор из
полного текста брал лишь `.ts`/`.js`: на Python-диффе всегда выходило `symbols 0/0 · skip:
no_symbols_in_diff`, хотя граф собран и свежий. Теперь символом считается и публичное (без
`_`) определение верхнего уровня — `def`, `async def`, `class` в колонке 0; добор идёт и по
`.py`/`.pyi`. Методы не берутся: `get`/`update` в графе неоднозначны и съели бы лимит
символов. На PR cod-doc с 120 файлами — 25 символов вместо 0, имена разрешаются
`graphify affected` как есть. JS и Rust; новый `rust/parity/diff.parity.mjs` сверяет оба
пути, включая границы строк, на которых JS-флаг `m` и Rust `(?m)` разошлись бы.

## 0.5.0 — обязательный blast-radius (RFC 16), пиктограммы, защита sticky — 2026-10-13

**Для потребителя — что меняется при обновлении пина с `v0.4.0`:**

- **Свой sticky и inline опознаются по автору, а не только по маркеру.** Список — новая
  `REVIEW_TRUSTED_AUTHORS` (по умолчанию `github-actions[bot]`; `REVIEW_FEEDBACK_TRUSTED_AUTHORS`
  — алиас). Если отчёты в вашем репозитории пишет PAT или GitHub App, задайте его логин —
  иначе первый прогон после обновления не узнает прежний sticky: создаст второй, Δ-блок
  начнётся без истории. Откат — `REVIEW_TRUSTED_AUTHORS=` (пусто: доверять любому автору).
- **Blast-radius обязателен в шаблоне CI.** `examples/ci/pr-review.yml` ставит новую
  `REVIEW_BLAST_REQUIRED=1`: если code graph не собран или graphify недоступен, ревью
  блокирует merge до LLM-вызовов и пишет причину в sticky. Скопировали шаблон, а граф не
  строите — уберите флаг или задайте `0`. Дефолт движка — `0`, без шаблона ничего не меняется.
- `graphifyy` в шаблоне CI и в `docs/model-tuning.md`: **0.9.52 → 0.9.87** (формат вывода
  `graphify affected` и строка `Built from commit` в отчёте не изменились; ключ кэша venv сменён).
- **Блок решает сама находка, а не её соседи по 3 строкам** (RFC 17). Пропадут блоки, где
  причиной в sticky стоял minor, critical с низкой confidence блокировал за счёт соседа или
  eslint-правило вне `blockRules` блокировало через соседнюю находку. В экспорте
  `consensusBlock` теперь только у блокирующей находки (форма артефакта та же).
- **Rename с правками и удалённые файлы ревьюятся** (RFC 17): раньше первый уходил в skip,
  второй был невидим роутеру. Такие PR теперь идут маршрутом full — больше LLM-вызовов.
- **Verifier проверяет блокеры сверх `REVIEW_VERIFIER_MAX` батчами** (новая
  `REVIEW_VERIFIER_BATCHES`, дефолт `3`) вместо молчаливого понижения в minor. Прежнее
  поведение — `REVIEW_VERIFIER_BATCHES=1`.
- **Сбой verifier'а — одно состояние «недоступен»** (RFC 18). Раньше упавший HTTP-вызов
  блокировал merge по слову агрегатора, а пустой ответ модели молча пропускал. Теперь находка
  уровня блока без вердикта из-за сбоя показывается как minor с пометкой, а прогон при
  `REVIEW_LLM_REQUIRED=1` (дефолт) блокируется как degraded с баннером «verifier недоступен —
  перезапустите». Пропускать merge при сбое — `REVIEW_LLM_REQUIRED=0`; прежнее поведение
  целиком — `REVIEW_VERIFIER_STRICT=0`. Из баннера блока убрана неверная фраза «Инфра-сбои
  merge не блокируют».
- **Часть PR, упавшая у всех моделей, больше не выдаётся за отревьюенную** (RFC 19).
  Раньше результат собирался из успешных чанков молча. Теперь при `REVIEW_LLM_REQUIRED=1`
  (дефолт) — degraded-блок «ревью неполное, перезапустите», при `0` — заметка. Пропуск по
  тайм-бюджету — по-прежнему заметка.
- Формат футера sticky, namespace маркеров, контракты `swarm` / `export` / `structure` —
  без изменений.

### Исправлено — покрытие по чанкам (RFC 19)

- `engine`: `failedChunks` и `skippedChunkIndexes` в результате модели (и резервной); `demoteAll`
  сохраняет индекс чанка.
- `pipeline.mjs`: чанк покрыт, если его отревьюила хоть одна модель; `coverageGap` → degraded по
  `REVIEW_LLM_REQUIRED`; событие `coverage_gap {failed, total, paths}`, поле в событии `gate`.
- Инкрементальный state: файлы непокрытых чанков (сбой и тайм-бюджет) не получают хэш — раньше
  они считались просмотренными и не ревьюились, пока не изменятся.
- `buildSummary` (JS и Rust): вход `coverageGap`, баннер «ревью неполное» без путей файлов.

### Исправлено — сбой verifier'а (RFC 18)

- `markVerifierUnavailable` (`pipeline.mjs`): исключение первого вызова, ни одного валидного
  вердикта, тайм-бюджет и сбой хвостового батча → `verifierStatus: unavailable`, severity → minor;
  `degradedBlock` по `REVIEW_LLM_REQUIRED` в коде выхода, `wouldBlock`, событиях `gate`/`verdict`.
- `buildSummary` (JS и Rust): вход `verifierUnavailable`, заголовок «⛔ ревью не завершено», баннер;
  `verdict.blocked` и `blocked` в истории прогонов учитывают degraded-блок.
- Событие `verifier_unavailable {reason, unverified}`.
- Инкрементальный state: файл с находкой `unavailable`/`overflow` не получает хэш, находка не
  переносится — перезапуск ревьюит файл заново, а не переносит непроверенное как minor.

### Исправлено — дыры гейта (RFC 17)

- `clusterFindings`/`resolveBlockers` (JS и Rust): `consensusBlock` и `confidenceBlock`
  считаются по находке; кластер даёт только счёт моделей. Блокер кластера — первая
  блокирующая находка; `pipeline.mjs` считает блокирующие кластеры по `some`.
- `dedupeAgainstPrescan`: LLM-находка снимается только prescan-находкой не ниже по severity.
- `isRenameOnlySection` (JS и Rust): убран ранний выход по `rename from`.
- `parseDiff` (JS и Rust): на `+++ /dev/null` путь из `diff --git`; `collectDeletedPaths` —
  prescan не запускается на удалённых файлах. Удаление распознаётся только по
  `deleted file mode` в заголовке секции; внутри хунка `+++`/`---` — содержимое: строка
  `++ /dev/null` в комментарии больше не выводит файл из prescan и не обрывает разбор файла.
- `runVerifierStage`: батчи по `REVIEW_VERIFIER_MAX`, одно применение вердиктов со сдвигом
  `candidateIndex`; сбой хвостового батча сохраняет проверенное. `stats.batches` в событии `verifier`.
- Фикстуры `gate-neighbour-minor-not-blocker`, `gate-neighbour-confidence-no-lift`,
  `gate-eslint-nonblock-via-neighbour` (eval: 20 seed-кейсов); parity-кейсы `rfc17 *`.

### Добавлено — `REVIEW_BLAST_REQUIRED` (RFC 16)

  перегрузки — одной карточкой, класс — с `constructor(…)`.

  из прошлого прогона, кроме файлов, чьи карточки указывают на файлы PR, и не больше одного
  прогона подряд).
- Новое: `REVIEW_VERIFIER_SYMBOL_CARDS` (по умолчанию выключено) — карточки во входе
  verifier'а; `pr-review-symbol-cards-probe` — офлайн-пробник отбора по истории репозитория.

- **Инкрементальный прогон** `REVIEW_INCREMENTAL=1` ([RFC 05](proposals/05-incremental-review.md)):

  переносится никогда. Прогон принудительно полный при смене конфигурации (модели, роли,
  гейт, порог маршрута/допуска verifier, таймаут LLM) и каждый
  `REVIEW_INCREMENTAL_FULL_EVERY`-й раз. В CI состояние требует `actions/cache` на
  `.ai-review/incremental/`; без него поведение прежнее.
- **Раскладка под префиксный кэш** `REVIEW_PROMPT_LAYOUT=shared-prefix` (RFC 04, решение 5):
  `[system: общая рамка] [user: контекст чанка] [user: инструкция роли]` — первые два

  роль лежала в `system`, и четыре вызова по чанку расходились с первого токена.

  Новый пробник `pr-review-probe-cache` замерил, даёт ли провайдер такую скидку. **На Ollama

  `usage` не сообщается) — поэтому дефолт `legacy` подтверждён замером, а не осторожностью, и
  раскладка ждёт провайдера с префиксным кэшем

### Исправлено

- **Router не считал кодом ничего, кроме JS/TS.** Список расширений в `lib/router.mjs`
  покрывал только JS/TS-семейство, поэтому PR, трогающий исключительно `.go`, `.py`, `.rb`,

  из 13 кейсов 9 на Python и Go уходили в `light` с нулём находок. Покрыто тестом
  «исходники не-JS языков — logic, а не other»
- **`fp` не доезжал до артефакта**: отпечаток кода считался только внутри `buildSummary`,
  в список для футера sticky. В экспорт уходил тот же массив находок, но без `fp`, и
  потребитель откатывался на дедуп по заголовку — переформулированная находка на той же
  строке считалась новой. Отпечатки проставляет `attachFingerprints` один раз на прогон,
  до ветвления «футер / Δ-блок / артефакт»; покрыто тестом «артефакт и футер показывают
  один отпечаток»
- **`actionabilityScore` был только у поднятых в инлайн** и в артефакте читался как
  «остальные не оценены». Скор и сигналы теперь пишутся каждой маршрутизированной находке,
  а роль «advisory поднята в строку» несёт отдельный флаг `actionabilityPromoted`:
  по нему авто-триаж не резолвит тред и инлайн печатает объяснение «почему в строке»
- **Слияние SCIP с graphify теряло сущности.** Ключ сопоставления был регистронезависимым
  (`путь + метка.toLowerCase()`), поэтому файл с `class User` и `const user` схлопывался:
  SCIP-данные про `User` приписывались `user`, вторая сущность исчезала из фактов, а рёбра
  на неё оставались висеть на несуществующем `observedId`. Теперь строгое совпадение метки
  важнее регистронезависимого, неоднозначный кандидат не сливается вовсе и попадает в
  `warnings`, а из набора выбывает ровно слитая сущность — не все делящие с ней ключ
- **`validateStructureFacts` не проверял ссылочную целостность**: битые `from`/`to` рёбер и
  `entityRef`/`targetRef` контрактов уезжали потребителю молча — валидатор смотрел только на
  массивы, лимиты, пути и fingerprint. Добавлена проверка: ссылка на неизвестную сущность
  теперь отклоняется
- **LCOV приписывал одноимённым функциям чужие хиты.** `FNDA` адресует функцию только по
  имени, а `FN` может объявить это имя в файле дважды (вложенные функции в разных областях —
  обычный JS): обе записи получали один счётчик, непокрытая функция объявлялась `covered` с
  чужими хитами вопреки собственному `DA` той же строки, и файл рапортовал полное покрытие
  функций. Теперь счётчик привязывается по порядку записей — istanbul пишет `FN` и `FNDA`,
  обходя один и тот же `fnMap`, поэтому N-я `FNDA` относится к N-й одноимённой `FN`. Такая
  привязка помечается `attribution: 'order'` и не претендует на `exact`: она опирается на
  поведение писателя, а не на ключ формата. Если числа записей разошлись (типично после
  слияния отчётов, где `FNDA` схлопнуты по имени), привязывать нечего — `hits: null`,
  observation со `status: unresolved` и `confidence: ambiguous`, имя в `warnings`, а
  знаменатель доли считается только по функциям с однозначным ответом
- **MCP-сервер не соблюдал собственный `inputSchema`.** Схема объявлена в `tools/list`, но
  аргументы не проверялись: `dependencyDepth` и размер ответа ограничены внутренними
  потолками `buildStructureContext`, а длина `scopeRefs`/`contractRefs` — ничем, при том что
  `matchesScope` перебирает список на каждую сущность. Границы теперь берутся из самой схемы,
  чтобы код и объявленный контракт не разъезжались
- **Страж varint в SCIP смотрел на сдвиг, а не на величину.** Varint, завершившийся на сдвиге
  49, мог выйти за 2^53: число теряло точность, портились низкие биты, и разбор падал с
  ложным диагнозом «truncated» — ошибка указывала не туда, где сломалось. Проверяется сама
  величина через `Number.isSafeInteger`
- **Граница «слой» строилась из имени файла.** `boundaryCandidates` брал второй сегмент пути
  под `appDir`, не проверяя, что за ним есть третий: `src/index.ts` превращался в границу
  `layer:index.ts`. На реальном графе (13437 узлов, `appDir: tools`) это давало 11
  выдуманных «слоёв» — `audit-all.mjs`, `package.json`, `vite.config.ts` и подобные, — и
  границ становилось 28 вместо 18. Слой теперь требует третьего сегмента. Заодно снят
  `else if`: путь под `appDir`, чей слой не заявлен в `layerDirs`, раньше не попадал ни в
  слой, ни в модуль и молча оседал в `boundary:repository` — теперь у него остаётся модуль.
  Границы влияют на `crossBoundary`, а значит на `dependencyRisk` и подсказки, поэтому у
  существующих репозиториев сместится `facts.fingerprint` — это работа фикса, не регрессия
- **Продюсер мог выдать факты, которые отвергает его собственная схема.** Сущности и рёбра
  ограничены потолками, а контракты — нет, хотя `structure-facts.v1.schema.json` объявляет
  `contracts: maxItems 5000`: на 5200 callable-узлах получалось 5079 контрактов. Появился
  потолок с предупреждением `contracts truncated at N`, и при обрезке первыми уходят
  эвристические `entrypoint` — доказанные `implements`/`inherits` остаются. `maxEntities` и
  `maxEdges` теперь клампятся к потолкам схемы: env-переменная не должна уметь сделать вывод
  невалидным. `validateStructureFacts` проверяет `contracts` и `boundaries` — раньше их не
  проверял никто
- **Метка god-узла помечала однофамильцев во всех файлах.** Сопоставление шло по
  `label.toLowerCase()` без пути, поэтому одна запись в `.graphify_analysis.json` помечала и
  `handler()` из `src/a.ts`, и `Handler()` из `src/b.ts`. Тот же класс дефекта, что в слиянии
  SCIP и в `FNDA`. Запись с `id` или `source_file` адресует узел точно; голое имя, которое
  разрешается больше чем в одну сущность, не помечает ничего и уходит в `warnings`
- **Узлы исчезали из фактов бесследно.** `normalizeRepoPath` бросает на небезопасном
  `source_file`, и `catch { continue }` глотал такой узел молча — по выходу нельзя было
  понять, целиком ли разобран граф. Отброшенные узлы и неразобранные `source_location`
  теперь считаются и попадают в `warnings`
- **Сгенерированный markdown врал о своей полноте.** `buildStructureMarkdown` режет подсказки
  на 50, сценарии на 200, хотспоты на 100 и не говорил об этом ни слова, тогда как блок
  «Data quality» в том же документе рапортовал `Truncated: no`. На реальном прогоне это 50
  показанных подсказок из 679 и 100 хотспотов из 678. Документ теперь называет, сколько
  строк он опустил
- **Значения из репозитория ломали разметку документа.** `esc` экранировал `|` и перевод
  строки, но не обратную кавычку, а `ruleId` и `remediation` не экранировались вовсе:
  перевод строки в `remediation` создавал заголовок, кавычка в пути рвала code span. Путь
  реальный — `remediation` подставляет `obligationRef` из obligations cod-doc. Значения в
  code span оборачиваются оградой длиннее самой длинной серии кавычек внутри, остальное
  проходит через `esc`
- **Упрочнение без живого дефекта** (проверено на реальном выводе Graphify, 13437 узлов и
  22097 рёбер): одинаковые рёбра дедуплицируются перед сортировкой — раньше дубль удваивал
  `fanIn`, потому что `assessDependencyRisk` считает по длине списка; в первом цикле
  контрактов появилась защита от повторного ключа, которая была только во втором; номер
  строки берётся до хвостовой колонки (`src/a.ts:10:5` → 10, а не 5) и понимается форма
  `#L10`. На этом производителе ни дублей рёбер, ни таких форм `source_location` нет —
  Graphify пишет только `L<n>`, — поэтому это защита от чужого формата, а не исправление
  наблюдаемой поломки

## 0.2.0 — вынос движка в самостоятельное решение


Первый релиз, в котором пакет не привязан к конкретному репозиторию. Движок синхронизирован
с рабочей версией потребителя (август 2026) и расцеплен с ней через профиль проекта.

### Добавлено

- **Профиль проекта** (`lib/profile.mjs`, [docs/profiles.md](docs/profiles.md)): маркеры
  комментариев, правила репозитория для промпта, раскладка каталогов для prescan, scope и
  allowlist ast-grep правил, пути feedback/observability/export — в одном JSON у потребителя.
  Источник: `REVIEW_PROFILE` → явное назначение → `.ai-reviewer.json` в корне → нейтральный
  дефолт. Битый профиль не роняет ревью (fail-open + строка в лог).
- **Маршрут находки по доказуемости** (`lib/actionability.mjs`): inline или свод решает сумма
  детерминированных сигналов (prescan, verifier, повтор, консенсус, чувствительная зона),
  а не ярлык severity. Пороги — `REVIEW_ACTIONABILITY_MIN`, `REVIEW_MAX_ADVISORY_INLINE`.
- **Δ-блок и история прогонов в sticky**: что появилось и что ушло с прошлого прогона;
  отпечаток кода у перенесённой находки (точный фикс снимает находку).
- **Метрики прогонов** (`lib/metrics.mjs`, `pr-review-metrics`): сводка по observability-логу.
- **Gold-набор** (`gold/`, `pr-review-gold`): shadow-прогон полного пайплайна с LLM на
  размеченных TP/FP диффах.
- Новые CLI: `pr-review-metrics`, `pr-review-gold`, `pr-review-probe-models`.
- Шаблоны workflow потребителя — [`examples/ci/`](examples/ci/) (ревью, harvest, promote, метрики),
  все на пиновом чекауте движка вместо копирования кода из базовой ветки.
- `test/profile.test.mjs` — поведение нейтрального профиля и загрузка чужого.

### Изменено

- Пакет переименован `@orakul/ai-reviewer` → **`ai-reviewer`**; дефолтные маркеры
  `<!-- ai-review -->`, SARIF `ai-review/<severity>`, файлы экспорта `ai-review.json` /
  `ai-review.sarif.json`. Прежние имена сохраняются профилем потребителя.
- Из движка убраны project-specific умолчания: пути `ops/pr-review/*` и `.graphify/*`,
  правила репозитория в промпте, allowlist `app/server/net.ts`, scope ast-grep правил,
  раскладка `app/<слой>` в prescan. Всё это теперь приходит из профиля.
- Пути данных по умолчанию — `.ai-review/*` в корне репозитория-потребителя.
- Fixtures и FP-паттерны движка резолвятся от корня пакета, а не от каталога проекта.
- Документация переписана под самостоятельный продукт; журнал FP конкретного проекта из
  пакета убран (он живёт у потребителя), в `docs/false-positives.md` осталось переносимое:
  семейства FP, встроенные защиты, петля обучения.
