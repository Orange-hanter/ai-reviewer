# Журнал разработки ai-reviewer

Живой лог решений и прогонов. Релизы по SemVer — в [CHANGELOG.md](../../CHANGELOG.md).
Сессионные отчёты — в [log/](log/). RFC пишутся **до** кода; этот журнал — что случилось после.

## 2026-10-16 — RFC 21: decision-модели, этап 0

**Зачем.** Появились decision-модели (Microsoft-Decision-1, gpt-6-luna-decisions, Jev):
закрытый набор вариантов → вероятность каждого. Разбор теории: вероятность — нормированное
правдоподобие варианта, калибровка только после подбора на своих метках, смещение по порядку
вариантов, слабость на многошаговом рассуждении, уверенные ошибки LLM-подстраховка повторяет
в 96% случаев. Отсюда — не в гейт и не в verifier, а на два решения по закрытому набору:
семейство FP находки и нужно ли чанку жюри.

**Решения владельца.** Этап 0 (офлайн) + этап 1 (shadow, вывод не меняется); модели
Decision-1 и luna; метки — автоматически из gold meta.

**Сделано:** [RFC 21](../../proposals/21-decision-models-shadow.md) (черновик);
[проба API](../probe-decisions-2026-10-16.md) — обе модели на одном эндпоинте OpenRouter
`/api/alpha/decisions`, перестановки внутри вызова у Decision-1 не различаются; секция
конфига `decision`; режим `decide` в бинаре `llm`; `lib/decision.mjs`; инструмент замера
`bin/pr-review-decision-eval.mjs`; [замер](../decision-stage0-2026-10-16.md).

**Не сделано:** gold-прогон упал на недельной квоте Ollama — положительных меток нет, этап 1
не открыт. Хуки shadow в `pipeline.mjs` (T6–T8) не писались: по плану только после go.

## 2026-10-15 — RFC 20: каскад и промпт в Rust, аудит JS-копий

**Сделано (PR #47).**
- Каскад ретраев LLM перенесён в `rust/src/llm/cascade.rs`. Добавлен ретрай на `low` с
  `+8000` токенов при 400 «Reasoning is mandatory».
- Системные промпты переписаны на английском в `rust/src/prompt.rs`.
- JS-копии объявлены deprecated.
- Живые проверки на OpenRouter: каскад на gemini, A/B жюри и проверка формата остальных
  ролей — RFC 20, § 4. Gold-прогон не делался по решению владельца (бюджет).

**Аудит JS-копий: ни один модуль сейчас удалить нельзя.**
- **B1 — потребитель бинарей не получает.** `rust/` нет в `files`, в
  `examples/ci/pr-review.yml` нет `cargo build`, готовых бинарей нет. У потребителя
  работает только JS, и правки RFC 20 до него не доходят.
- **B2.** Резолверы захардкожены на `rust/target/debug/<mod>`.
- **B3.** Тесты, которые сами держат JS-путь:
  - `test/github.test.mjs` весь на DI-fetch;
  - `diff-line-terminators` и `findings-advisor-claims` форсируют FORCE_JS.
- **B4.** Устаревший бинарь молча даёт старое поведение. Защита (JS-backfill) есть
  только у config.
- **B5. Пробелы parity:**
  - у llm parity-скрипта нет;
  - у diff не сверяются `parseDiff`/`buildChunks`.
- **B6. Нет lookahead в Rust-regex.** На JS держатся FP-фильтр
  (`matchesKnownFalsePositive`), `layout.sensitive` и `layout.e2eSpec`. Для prompt
  деградация при lookahead в e2eSpec незаметно меняет вход модели на промпт 0.5.1.
- **Не удаляемы вовсе** (единственная реализация или нужны в рантайме):
  - `computeConfigPartsJs` (backfill на каждом `loadReviewConfig`);
  - `lib/structure.mjs`;
  - `lib/structure-drift.mjs`;
  - JS-only оркестрация (`createReviewEngine`, `createVerifierRunner`, `createObservability`, профиль, fs-функции).
- **Удалимы после B1:**
  - router, report, specialists, export, metrics, json;
  - копии engine;
  - 9 модулей structure-* с parity.
- **Удалимы после B1 и доработки:**
  - prompt, actionability (B6);
  - verifier — ветка `allFrom`, `lib/verifier.mjs:81,149`;
  - github — перевести тесты на фейковый HTTP;
  - diff (B5).

**Решение по B1 (владелец):** готовые бинари в релизе. Сделаны три части:
- `release-binaries.yml`;
- шаг `Download engine binaries` в шаблоне потребителя;
- поиск бинарей `lib/rust-bin.mjs` (заодно закрыт B2).

Проверено локальной симуляцией потребителя. Архив упакован тем же циклом, что в workflow,
`target/` спрятан, бинари лежат только в `rust/bin`. Результат: обёртки берут бинари из
`rust/bin`, промпт новый, каскадные тесты зелёные.

В полном `npm test` в этом режиме падают два теста `cursor-plugin` «fail-fast < 2000 мс»
(2.5 с). Отдельно они проходят. Гипотеза (не проверена): macOS сканирует свежескопированные
неподписанные бинари при первом запуске и нагружает машину. На Linux-раннере это не
воспроизвести без релиза.

Реального прогона workflow ещё не было: он запустится на первом релизе после мержа.

## 2026-10-09 — fp-noise: «ложная блокировка» оказалась настоящей находкой

**Разобрано.** Gold-кейс `fp-noise-no-real-blockers` блокировал в 8 из 9 прогонов. Блокировали не старые FP PR #477, а: выбор sticky по маркеру без проверки автора (7 раз), «утечка таймеров AbortController» (2), Markdown-инъекция (1); каждую подтверждал verifier. Первая — настоящая и была в текущем коде; таймеры — FP (семейство 8 в [false-positives](../false-positives.md)); Markdown — косметика. Гейт работал правильно, устарела разметка.

**Сделано.** Свой sticky/inline = маркер + автор из `REVIEW_TRUSTED_AUTHORS`; `readChangedFiles` — containment через realpath (тот же класс, что был закрыт в карточках символов); экранирование текста модели в секциях «вне строк диффа» и «FP». Кейс переразмечен в `tp`: `wouldBlock: true`, локация `github.mjs:81–91`, старые FP — в `mustNotFindTitles`.

**Уточнение.** Поддельный sticky не блокирует merge сам: carry-over находок идёт из state-файла инкрементального режима, а футер sticky питает промпт агрегатора, Δ-блок и `priorKeys` actionability.

**Открыто.** Gold ×3 по кейсу после мержа; auto-triage сверяет GraphQL `author.login` (без суффикса `[bot]`) с дефолтом `github-actions[bot]` — вероятно, никогда не совпадает ([backlog](../backlog.md)).

## 2026-10-08 — RFC 14: замер шага 0

**Сделано:** CARD-002. Без LLM, на имеющихся данных; цифры и выборка — в [RFC 14, «Замер»](../../proposals/14-symbol-cards.md).

**Исход.** Утверждений «символ `X` не определён» — 0 из 208 уникальных заголовков (272 прогона + публичный бенчмарк); тела находок наблюдаемость не хранит. ## 2026-10-08 — RFC 14 принят: карточки символов

**Зачем.** Модель не видит объявлений того, что вызывают изменённые строки, если объявление вне окна или вне PR: отсюда ложное «`X` не определена» и гипотезы о контракте вызываемой функции. Правило (c) в промпте запрещает вывод, но знания не даёт.

**Решения.** Дерево или outline репозитория в промпт — нет: цена на каждый вызов и поломка инкрементального прогона. Предварительная модель, которая собирает дерево или пишет сводки символов, — нет: её непроверенная ошибка едет одним входом к advisors, жюри и verifier и становится согласованной ошибкой обоих судей. Принято: шаг 0 — замер без LLM; шаг 1 — FP-семейство 8 по графу Graphify; шаг 2 — карточка как строка объявления с диапазоном из файла; шаг 3 — ранкер на дешёвой модели только по метрике переполнения. Конец объявления — лексер без зависимостей (в графе только начало, `endLine` SCIP — конец имени); номера строк в хэш RFC 05 не входят, иначе любой сдвиг строк пере-ревьюит всех вызывателей. Окно verifier по границам функции — следующее отдельное решение.

**Сделано:** [RFC 14](../../proposals/14-symbol-cards.md) (PR #22, статус — PR #23); план `symbol-cards` в cod-doc, CARD-001…012. Следующая — CARD-002, замер. Частота обеих ошибок сейчас не известна: от замера зависит, нужны ли секции C и D.
