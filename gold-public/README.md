# gold-public — публичный набор для замера precision/recall

Набор из чужих репозиториев. Отвечает на вопрос, на который `gold/` ответить не может:
насколько движок точен на коде, который мы не писали и не размечали под себя.

Решения зафиксированы в [RFC 03](../proposals/03-public-benchmark-dataset.md), методология —
в [docs/benchmark.md](../docs/benchmark.md).

## Кейс — это только `meta.json`

Чужие диффы **не вендорятся**: в каталоге кейса лежит одна мета с пином
`source.{repo, pr, sha}`, а патч тянется по `sha` в `REVIEW_GOLD_CACHE`
(`.ai-review/gold-public`, gitignored). Причина — лицензии чужих репозиториев
(AGPL/GPL/FSL) и вес монорепо-диффов; воспроизводимость держит пин на неизменяемый коммит.

```bash
node bin/pr-review-gold-harvest.mjs --validate gold-public   # сверить разметку с диффами
OLLAMA_API_KEY=… npm run benchmark:public                    # прогон + сводка
```

## Откуда разметка

SZZ-lite: ground truth — решение самого проекта, а не наше суждение о чужом коде.

1. Смерженный PR-**фикс** ссылается на PR-**виновника** («regression introduced in #N»).
2. Дифф виновника (пин по `merge_commit_sha`) — кейс.
3. Локация дефекта — сопоставлением **текста**: строка, удалённая фиксом, ищется среди
   строк, добавленных виновником. Номер берётся из диффа самого кейса, поэтому дрейф файла
   между двумя PR разметку не смещает.

`--validate` проверяет главное свойство разметки: каждая локация обязана указывать на
строку, которую этот дифф действительно добавил. Все 22 локации 13 кейсов проверку проходят.

## Отбор: 13 из 42

Харвестер готовит кандидатов, но не решает, годен ли кейс. Из 42 кандидатов
(grafana 12, sentry 20, discourse 5, cal.diy 6, после схлопывания бэкпортов) оставлено 13.

**Критерий отбора один и применён единообразно:** остаётся дефект логики — тот, который
рецензент в принципе может увидеть в диффе. Отбраковано 29 кандидатов, из них подавляющее
большинство — **презентационные регрессии** (курсор, hover, паддинги, стили, порядок
элементов, «мигающие иконки»): их нельзя увидеть в диффе, их видно только в отрисовке, и
требовать их от ревью по диффу нечестно.

Число отбракованных публикуется намеренно: без него ручной отбор превращается в подгонку.

## Как читать цифру

Набор меряет **recall по известным дефектам**, а не абсолютный recall: SZZ-пара доказывает,
что дефект был, но не что он единственный в диффе. Выборка смещена в сторону дефектов,
которые проект заметил и связал ссылкой с виновником.

`clean`-контроль — PR, на который за 400+ дней не сослался ни один другой PR.

⚠️ **Это НЕ измеряет precision, и блокер здесь НЕ считается ложным.** Первый замер это
доказал: ручной разбор всех 7 блокирующих находок на трёх заблокированных clean-контролях
не нашёл ни одной ложной — в двух PR лежали настоящие дефекты, которых никто не заметил
(потому фикса со ссылкой и не было). Отсутствие ссылающегося фикса доказывает лишь
отсутствие **замеченного** дефекта.

Поэтому clean-контроль меряет **долю произвольных смерженных PR, на которых гейт поднимает
блок**. Precision получается только после ручного разбора находок, и разбор публикуется
вместе с цифрой — см. [docs/benchmark-public.md](../docs/benchmark-public.md).
