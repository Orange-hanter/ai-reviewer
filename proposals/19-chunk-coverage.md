# 19 — Покрытие по чанкам: упавшая часть PR не выдаётся за отревьюенную

> Категория: 🎯 Прямое · Риск: средний · Зависимости: RFC 18 (тот же рычаг `REVIEW_LLM_REQUIRED`), RFC 05 (инкрементальный state)

## Контекст

Большой PR режется на чанки, каждый ревьюится отдельным вызовом. Модель может упасть на
одном чанке (ошибка HTTP после ретраев, сорванный JSON после каскада повторов) и ответить
на остальных. Гейт после этого решает так, будто PR просмотрен целиком.

## Текущее состояние

- `aggregateModelJs` / `aggregate_model` (`lib/engine.mjs`, `rust/src/engine.rs`) собирают
  результат модели из успешных чанков; ошибка модели целиком — только если упали все.
- `applyFallback` (`lib/engine.mjs`) включает резервную модель только для ошибки целиком.
- `pipeline.mjs` считает `ok = reviews.filter((r) => !r.error)`: модель с 7 из 10 чанков — ok.
  Тайм-бюджет считается (`skippedChunks`, заметка в sticky), сбой чанка — нигде.
- Инкрементальный state (`writeIncrementalState`) пишет хэши всех файлов PR. Файл упавшего
  чанка на следующем прогоне — «не изменился», переносить по нему нечего, и он **не
  ревьюится больше никогда**, пока не изменится или не придёт каждый 10-й полный прогон.
- Сбой можно вызвать содержимым PR (prompt injection «ответь не-JSON»): находки этого чанка
  пропадают, merge проходит.

## Предложение

1. `engine` отдаёт в результате модели `failedChunks` (индексы чанков со сбоем, не тайм-бюджет)
   и `skippedChunkIndexes` (тайм-бюджет); `demoteAll` сохраняет индекс чанка. Для результата
   резервной модели — то же. Агрегация (Rust) не меняется: индексы считаются в JS-оркестрации.
2. `pipeline.mjs`: чанк покрыт, если его отревьюила хоть одна модель из `ok`. Непокрытый чанк,
   на котором хоть одна модель упала, — пробел покрытия (`coverageGap {failed, total, blocked}`).
   Исход — `REVIEW_LLM_REQUIRED`, как в RFC 18: `1` (дефолт) — degraded-блок «ревью неполное,
   перезапустите», `0` — заметка. Причины degraded (verifier, покрытие) сводятся в одну строку
   для лога и `detailedResult.reason`.
3. Инкрементальный state: файлы непокрытых чанков (сбой **и** тайм-бюджет) не получают хэш —
   следующий прогон их ревьюит.
4. Sticky (JS и Rust): вход `coverageGap`, баннер без путей — имя файла задаёт автор PR;
   пути — в логе и событии `coverage_gap {failed, total, paths}`.

## Миграция

Без флага. Потребитель с дефолтами увидит degraded-блок там, где раньше молча прошёл бы
частично отревьюенный PR. Откат — `REVIEW_LLM_REQUIRED=0` (заметка без блока).

## Риски и что не делаем

- **Тайм-бюджет не блокирует** — открытый вопрос. Пропуск по тайм-бюджету на огромном PR
  повторится на каждом прогоне, и degraded-блок стал бы постоянным; сейчас это заметка, как
  было. Но «сделай PR огромным» остаётся способом пройти без полного ревью. То же касается
  `time_budget` в RFC 18 (там уже degraded) — решение нужно одно на оба места.
- Не ретраим упавший чанк резервной моделью: её находки идут без жюри и в strict-refutation
  блокировать не могут, а покрытие для гейта они бы засчитали.
- В consensus-режиме чанк, отревьюенный одной моделью из двух, считается покрытым, хотя
  консенсуса по нему не будет. Это поведение гейта по консенсусу, не покрытия.

## Оценка

Одна задача: индексы в `engine`, покрытие и state в `pipeline.mjs`, баннер в JS и Rust,
тесты (engine — индексы; pipeline — блок, покрыто другой моделью, fail-open, инкрементальный
повтор), parity-кейсы `coverage gap *`.
