# 04 — Экономия токенов без потери качества: что режем и чем доказываем

> Категория: 🔵 Архитектура · Риск: средний · Зависимости: нет (RFC 03 — источник методики замера)

## Контекст

Прогон стоит дорого, а отдача слабая. Замер на реальных прогонах из
`.ai-review/observability/pr-review-runs.jsonl` (6 прогонов, 205 LLM-вызовов) и логе
`pr-6-run.log`:

| Прогон PR #6 (264 КБ диффа, 35 файлов, sonnet во всех ролях) | |
|---|---|
| Вызовов | 48 (12 чанков × 3 специалиста + 12 агрегаторов) + 1 verifier |
| Токенов | 1.3M |
| Время | 17 минут |
| Находок | 34 |
| **Дошло до строки в PR** | **1 инлайн**, 33 «вне строк диффа» |
| Блокеров | 0 |

Стабильность набора между прогонами одного и того же PR — `0.08–0.2` (события `stability`):
прогон за прогоном движок выдаёт другие формулировки того же. Это значит, что заметная часть
из 1.3M токенов оплачивает не поиск дефектов, а ротацию слов.

Разложение входа (замер `parseDiff`/`readChangedFiles`/`buildChunks` на `pr-6.patch`):

- дифф — 308 КБ, контекст файлов — **402 КБ**;
- **26 из 35 файлов добавлены этим PR** (246 КБ из 264 КБ диффа): их «полный контекст» —
  дословная копия собственного диффа;
- **5 из 14 чанков не содержат кода** (plan.md, docs, JSON-схемы, fixtures) и всё равно
  получают все четыре вызова; специалисты по ним отвечают «в моей области замечаний нет»;
- blast-radius пуст во **всех шести** прогонах (`graph missing`), prescan даёт **0** находок —
  но инструкции про них едут в каждом промпте;
- половина вызовов kimi (16 из 34) и четверть minimax (9 из 34) на Ollama Cloud завершились
  `aborted` по таймауту 240 с — вход оплачен, ответа нет.

## Текущее состояние

Сверено по коду `main`, не по памяти:

- [`pipeline.mjs`](../pipeline.mjs) — `readChangedFiles(files, limits, log)` читает **каждый**
  изменённый файл целиком (до `REVIEW_MAX_FILE_LINES=1500` строк) и кладёт в `contentMap`;
  `buildChunks` раскладывает контент по первым кускам файлов;
- [`lib/engine.mjs`](../lib/engine.mjs) `runMoAOverChunks` → `reviewChunkMoA`: **на каждый
  чанк** зовёт всех `specialists.assignments` (3 роли), затем агрегатора. Состав ролей не
  зависит ни от содержимого чанка, ни от того, совпадают ли модели ролей;
- [`lib/prompt.mjs`](../lib/prompt.mjs): роль лежит в `system`-сообщении
  (`buildSpecialistMessages`), а `buildSpecialistAggregatorMessages` **дописывает** секцию
  референсов в начало последнего `user`-сообщения. Итог: четыре вызова по одному чанку не
  делят общего префикса ни на байт — префиксный кэш провайдера невозможен по построению;
- [`lib/specialists.mjs`](../lib/specialists.mjs) `applyRefutation(..., { strict: true })`
  (так зовёт `pipeline.mjs`): находка уровня `critical`/`major` **без `advisorClaims`**
  понижается до `minor`. Это и есть механизм «нет жюри — нет блока»;
- [`lib/verifier.mjs`](../lib/verifier.mjs): Pass B независим от агрегатора и работает по
  всему набору кандидатов, вне зависимости от того, какой чанк их породил;
- `MOA_REFERENCE_MAX_TOKENS=12000` на роль ([`lib/config.mjs`](../lib/config.mjs)), число
  пунктов в ответе специалиста ничем не ограничено.

## Предложение

Пять решений. Первое уже реализовано (тривиально и без риска), остальные — предмет этого RFC.

### 1. Добавленный файл не прикладывается контекстом · 🎯 риск низкий · **сделано**

`collectAddedPaths(diff)` в `lib/diff.mjs` собирает пути с `new file mode`; для них
`readChangedFiles` кладёт указатель `«новый файл — его содержимое целиком в диффе ниже»`
вместо тела. Символы blast-radius не теряются: `collectBlastSymbols` разбирает `changedText`,
куда строки добавленного файла уже попали. Флаг `REVIEW_SKIP_ADDED_FILE_CONTEXT` (default on).

Указатель, а не пустота — намеренно: пустой `contentMap` для файла превращается в находку
«кода не видно», ровно то FP-семейство, против которого написан `buildChangedFilesSection`.

### 2. Состав ролей зависит от содержимого чанка · 🔵 риск средний

**Правило:** чанк, в котором нет ни одного **исполняемого** файла, обслуживается **одним**
вызовом агрегатора, без специалистов. Флаг `REVIEW_CHUNK_ROUTING` (default on), решение
логируется в `plan`.

Исполняемым считается файл, который: класса `logic` по
[`classifyFilePath`](../lib/router.mjs) (код); либо запускается или конфигурирует запуск
(`.yml`/`.yaml`/`.sh`/`.sql`/`.tf`, `Dockerfile`, `Makefile`, всё под `.github/`); либо
попал в `layout.sensitive` профиля (авторизация, деньги, миграции, гейты). Остальное —
данные и текст: `.md`, `.json`-схемы и fixtures, `.txt`, снапшоты.

Класс `config` роутера для этого решения не годится напрямую: он одинаково метит
`.github/workflows/deploy.yml` и `fixtures/structure/obligations-export.v1.json`. Первый
заслуживает трёх специалистов, второй — нет.

**Что это меняет в гейте — и почему это допустимо.** У находок такого чанка не будет
`advisorClaims`, поэтому `applyRefutation(strict)` понизит `critical`/`major` до `minor`:
**находка из чанка без кода не сможет заблокировать merge**. Это осознанный обмен, а не
побочный эффект:

- он согласован с уже принятой политикой роутера: docs-only PR уходит в `light` и **вовсе не
  ревьюится LLM** (`routeDiff`). Считать docs-чанк внутри смешанного PR более достойным
  блокировки, чем docs-PR целиком, — непоследовательно;
- он идёт в сторону fail-open, а пакет фейлится открыто по умолчанию (`bin/pr-review.mjs`
  ловит всё и выходит `0`);
- находки не теряются: они остаются в отчёте как `minor`, попадают в артефакт и в carry-over;
- на замере из шести прогонов ни один блокер не пришёл из чанка без кода.

**Что НЕ делаем:** не пропускаем такие чанки целиком (потеря находок), не трогаем маршрут
`skip`/`light` роутера, не меняем `strict`-семантику `applyRefutation`.

### 3. Выход специалистов ограничен тем, что доезжает · 🎯 риск низкий

`MOA_SPECIALIST_MAX_ITEMS` (default 8) в промпт роли + `MOA_REFERENCE_MAX_TOKENS` 12000 → 4000,
и требование: `minor` только с дословной цитатой и конкретным фиксом, `nit` не репортить.

Обоснование прямое: из 34 находок PR #6 до строки доехала одна, а 33 ушли в свод «вне строк
диффа», который никто не читает. Платить за них выходными токенами специалиста, потом
входными токенами жюри, потом работой refutation — три раза за один шум.

**Гейт решения:** gold-recall не ниже базы. Если падает — откатываем лимит, а не качество.

> Реализовано с отклонениями: env `MOA_SPECIALIST_MAX_ITEMS` не заведён — лимит зашит
> константой `SPECIALIST_MAX_ITEMS = 8` в `lib/prompt.mjs`; `MOA_REFERENCE_MAX_TOKENS`
> снижен до 6000, а не 4000 (`lib/config.mjs`, CHANGELOG 0.3.0).

### 4. Один вызов вместо трёх, когда роли сидят на одной модели · 🟡 риск низкий

`REVIEW_SPECIALISTS_MERGE=auto|always|never` (default `auto`): при совпадении моделей всех
`specialists.assignments` — один вызов с тремя размеченными секциями, ответ режется по
заголовкам обратно в три `references` с прежними `role`. Для `mergeSpecialistReferences`,
жюри и refutation ничего не меняется — на вход им приходит та же структура.

Основание: три «независимых критика» на одной модели с одним контекстом независимы только на
бумаге (случай локального прогона по подписке: `security=sonnet, correctness=sonnet,
architecture=sonnet`). Платить за независимость, которой нет, — чистый убыток.

### 5. Общий префикс ради кэша провайдера · 🔵 риск средний · **сделано под флагом**

`REVIEW_PROMPT_LAYOUT=shared-prefix` перестраивает сообщения в
`[system: общая рамка] [user: контекст чанка] [user: инструкция роли]`. Первые два сообщения
побайтово равны у всех ролей чанка, роль приезжает последней — заодно ближе к концу окна,
где модели держат инструкции лучше.

**Порядок сообщений не стал контрактом с `rust/src/prompt.rs`.** Раскладка собирается в
`lib/prompt-layout.mjs` из уже готовых сообщений: тексты ролей продолжает строить
`lib/prompt.mjs` и его Rust-порт, здесь только перестановка. Поэтому паритетной копии у
модуля нет и расходиться сторонам нечем.

Разбор проверяет форму и при несовпадении возвращает `null` — вызывающий остаётся на прежней
раскладке. Собрать «почти правильный» промпт хуже, чем не сэкономить: у агрегатора мнения
советников приписаны спереди к последнему `user`, и неверный срез отрезал бы часть контекста
молча.

**Дефолт `legacy`.** Выигрыш зависит от провайдера: OpenAI-совместимые кэшируют общий префикс
сами, Anthropic требует явных `cache_control`-маркеров, а через шим `claude -p` кэш вообще не
управляется нами. Плюс порядок сообщений влияет на находки. Поэтому включение — решение
оператора после замера; `cache_prefix_chars` в событии `llm_call` показывает, сколько входа
лежит в общем префиксе, то есть верхнюю границу выигрыша.

**Замер на нашем провайдере опроверг ожидание** (`pr-review-probe-cache`, префикс ~6k токенов,
по три вызова на модель):

| Модель (Ollama Cloud) | Повтор того же префикса | Другой префикс (контроль) | Кэш в `usage` |
|---|---|---|---|
| `kimi-k2.7-code` | 1445 мс | 1330 мс | не сообщается |
| `minimax-m3` | 1308 мс | 944 мс | не сообщается |

Повторно присланный префикс не дешевле и не быстрее контрольного — **Ollama Cloud скидки за
общий префикс не даёт**, и на этом провайдере решение 5 экономии не приносит. Раскладка
остаётся в пакете: она бесплатна, когда выключена, и включается одной переменной на провайдере,
который кэш поддерживает (проверять — тем же пробником). Дефолт `legacy` подтверждён замером,
а не осторожностью.

## Миграция

Все пять — под флагами с дефолтом «включено» (кроме 5, который не меняет наблюдаемого
поведения). Откат — одна переменная окружения, поэтому решения обратимы; необратим только
эффект на историю прогонов, для чего в RFC 03 уже заведена отметка о смене базы.

Каждый шаг документируется в `docs/configuration.md`; смена дефолтов моделей и температур не
входит в этот RFC.

## Риски и что не делаем

- **Риск:** правило 2 маскирует настоящий блокер в CI-workflow или в чувствительном пути.
  Смягчение: признак «исполняемое» покрывает `.yml`/`.sh`/`.sql`/`Dockerfile`/`.github/**` и
  `layout.sensitive` профиля — такие чанки полный MoA сохраняют, урезаются только данные и
  текст.
- **Риск:** правило 3 срежет длинный хвост, в котором изредка сидит настоящий дефект.
  Смягчение: gold-гейт, лимит конфигурируем.
- **Не делаем:** не трогаем `resolveBlockers`, `REVIEW_BLOCK_ON`, веса `actionability` и
  формат футера sticky — контракт с потребителем не меняется.
- **Не делаем:** не вводим свой embedding-индекс и не меняем состав моделей.

## Оценка

| Шаг | Задач | Ожидаемый эффект на замере PR #6 |
|---|---|---|
| 1 (сделано) | 1 | вход 710 КБ → ~465 КБ |
| 2 | 1 | 48 → ~34 вызова |
| 3 | 1 | выход −50%, вход жюри −30% |
| 4 | 1 | ~34 → ~22 вызова (на конфигурации с одной моделью) |
| 5 | 2 | оплачиваемый вход −60% там, где провайдер кэширует префикс |

Доказательство эффекта — `efficiencyMetrics` в `run_end` (токены на инлайн/блокер) и
gold-прогон до/после каждого шага. Шаг, ухудшивший recall, откатывается.

**Что показал замер.**

- Суммарный вход не сократился: 692 221 → 700 890 (+1,3 %). Условные абзацы промпта и
  компактная карта PR режут десятки-сотни символов на вызов, тогда как вход держат дифф и
  контекст файлов: `prompt_chars` специалистов 1 127 132 → 1 123 844 (−0,3 %), агрегатора
  490 549 → 481 504 (−1,8 %).
- Сократился выход жюри на единицу результата: completion-токенов агрегатора на находку
  5 912 → 3 982 (−33 %) при росте числа находок агрегатора 17 → 24.
- Цена доезда упала: токенов на инлайн 138 444 → 58 408 (−58 %).
- `REVIEW_VERIFY_ADVISORY_MIN` (порог допуска 1 против порога маршрута 4) дал 15
  advisory-кандидатов на три кейса, из них **9 прошли только по пониженному порогу**
  (событие `verifier_advisory`: 5/2, 5/5, 5/2). На `tp-real-bugs-unescape` verifier до прохода
  вовсе не вызывался (`verifier_skip: no_candidates`) — теперь вызывается.
- Эффект окон verifier'а из JSONL не измеряется: `prompt_chars` пишется только для вызовов
  движка (`lib/engine.mjs`), у `callType: 'verifier'` этого поля нет ни в одном прогоне.

**Recall не ниже базы.** Ни один ✅ не стал ❌; `tp-structure-real-defects` нашёл на одну
размеченную локацию больше (2 из 4 против 1 из 4); `tp-real-bugs-unescape` остался ❌ с теми же
двумя подсказками. Гейт «шаг, ухудшивший recall, откатывается» пройден.

**Эксперимент A5 (`REVIEW_AGGREGATOR_REASONING_EFFORT=none`) — отклонён.** Экономии нет:
completion-токены агрегатора 95 563 → 100 754 (+5,4 %), суммарные токены 700 890 → 714 996
(+2,0 %). Качество ниже: `fp-noise-no-real-blockers` перешёл ✅ → ❌ (2 блокера на кейсе без
реальных блокеров), `tp-structure-real-defects` потерял найденную локацию
`structure-drift.mjs:168-189`. Дефолт `low` в `lib/config.mjs` и `rust/src/config.rs` остаётся.
