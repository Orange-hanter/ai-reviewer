# Аудит RFC 14 «Карточки символов» после включения по умолчанию

> Объект: [RFC 14](../../../proposals/14-symbol-cards.md), реализация на `bbc7d7a` (PR #26) —
> `lib/symbol-cards.mjs`, проводка в `pipeline.mjs`, блок в `lib/prompt.mjs` /
> `rust/src/prompt.rs`, `limits.symbolCards*`, хэш RFC 05. Метод: независимый разбор кода
> (не брифа) отдельной моделью + офлайн-прогон отбора карточек на графе Graphify стороннего
> TS-репозитория (NestJS, 5669 узлов, 40 коммитов, 121 файл: 707 кандидатов → 84 карточки,
> из них 3 вводят модель в заблуждение). Ключевое утверждение (п. 0.1) перепроверено вручную.

## Итог

Карточка не может создать ложную блокировку: блокер требует вердикта verifier, а он
карточек не видит. Худший исход — шумовая minor-находка или потерянная верная. Готовность —
**условная**: до того, как считать фичу готовой, закрыть 0.1, 0.2, 1.1–1.3 и метрику 1.5.

## 2. Методология решений

- **Отмена шага 1.** «0 из 208» — заголовки при действующем запрете (c) в промпте: класс не
  виден, а не отсутствует. Отмена оправдана, если есть датчик по телам (1.5).
- **Включение по умолчанию.** n=1 на конфигурацию, 9 кейсов, набор карточек не
  прод-эквивалентен (0.3) — «вреда не найдено» слабая граница. Добрать: 3 прогона на
  решающих кейсах (`fp-noise-no-real-blockers`, `tp-structure-real-defects`,
  `tp-real-bugs-unescape`); офлайн-пробник точности карточек на 2–3 живых репозиториях;
  shadow у потребителя с метриками 1.5.

## 3. Вектор развития (приоритет)

1. Точность карточек: 0.2, 1.1–1.3, 1.7 — мера: офлайн-пробник, вводящих в заблуждение ≤ 1 %.
2. Наблюдаемость: 1.5 — без неё остальное не измерить.
3. Карточки verifier'у (1.4) — меняет вход второго судьи: раздел RFC и gold ×3.
4. Разрешение через импорт вызывающего файла вместо уникальности имени (снимает большую
   часть `unresolved_or_ambiguous`, открывает `ns.fn(`).
5. Сигнатуры TS (1.6).
