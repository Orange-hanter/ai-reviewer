# 15 — Наряды по косвенным признакам: разведка вместо равномерного внимания

> Категория: 🔵 Архитектура · Риск: средний · Зависимости: [RFC 04](04-token-economy.md) (методика замера, бюджет вызовов), [RFC 07](07-windowed-file-context.md) (окна контекста — точка приложения этапа 1), [RFC 03](03-public-benchmark-dataset.md) (разметка, на которой всё проверяется)

## Контекст

Публичный замер ([benchmark-public.md](../docs/benchmark-public.md)) дал location recall
**4/13 (31%)** при **нуле ложных блокировок** на clean-контролях. Разбор всех семи
блокирующих находок показал: движок не выдумывает, он **смотрит не туда**. Два кейса
формулируют это точнее любого среднего:

- `sentry-39016` — гейт заблокировал merge **верно**, но ни одна находка не встала на
  строки, которые проект потом чинил;
- `sentry-78722` — находка попала **точно** в размеченную строку, но жюри понизило её до
  minor, и merge прошёл.

Вердикт и адресация разошлись. Это не дефект промпта и не нехватка модели: это следствие
того, что **один вызов исполнителя делает две разные работы**. Сначала поиск — «где в этом
чанке может быть дефект», — и только потом суждение — «дефект ли это». Поиск ведётся по
равномерно поданному контексту: 40 строк вокруг каждой изменённой строки каждого файла,
одинаково для горячего и холодного.

Поиск в длинном равномерном контексте — ровно та задача, на которой модели измеримо
деградируют: точность падает более чем на 30% при смещении релевантного фрагмента в середину
(Liu et al., TACL 2024), а для локализации внутри файла показан отдельный краевой эффект
(Sovrano et al., FSE 2025). Суждение по адресу — задача проверки, на которой те же модели
сильны; на ней и держится verifier Pass B.

Предложение: **работу поиска выполняет детерминированный слой косвенных признаков**, за
миллисекунды и без единого токена, а исполнитель получает не чанк, а **наряд** — где
смотреть, какая гипотеза, сколько контекста, какая роль.

## Текущее состояние

Сверено по коду.

**Внимание распределено равномерно — в трёх местах.**

- [`lib/prompt.mjs:542`](../lib/prompt.mjs) `buildSpecialistMessages(role, baseMessages)`
  берёт `user`-сообщение базовых messages **как есть** и подменяет только системный промпт:

  ```js
  const user = (baseMessages || []).find((m) => m.role === 'user')?.content || '';
  return [{ role: 'system', content: specialistRules(role) }, { role: 'user', content: user }];
  ```

  То есть `security`, `correctness` и `architecture` получают **байт-в-байт одинаковый**
  контент и различаются одним абзацем `SPECIALIST_FOCUS[role]` ([`lib/prompt.mjs:135`](../lib/prompt.mjs)).
  Адресности по ролям в движке нет вообще.
- [`lib/chunk-routing.mjs:33`](../lib/chunk-routing.mjs) `chunkNeedsSpecialists` — решение
  всё-или-ничего: чанк либо получает все роли, либо только агрегатор. Подмножества ролей нет.
- [`lib/context-window.mjs:98`](../lib/context-window.mjs) `windowChunkFileContents(contentMap, files, { margin, minChars })`
  режет окна ±`margin` вокруг `validLines` — **один и тот же margin для всех файлов чанка**
  ([`pipeline.mjs:421`](../pipeline.mjs)). Файл, где меняется одна строка в мёртвой ветке, и
  файл, где переписан обработчик, платят одинаково.

**Маршрутизация работает только на уровне прогона.** `routeDiff`
([`lib/router.mjs:178`](../lib/router.mjs)) выдаёт `skip | light | full`; внутри `full`
пофайлового или похунквого отбора нет.

**Детерминированные сигналы уже считаются — и не используются для распределения внимания.**
Prescan ([`pipeline.mjs:406`](../pipeline.mjs)) и blast-radius
([`pipeline.mjs:429`](../pipeline.mjs)) дают находки и промпт-секции, но не влияют ни на
состав ролей, ни на размер окна. Класс пути (`classifyFilePath`) уже мемоизирован в пайплайне
([`pipeline.mjs:452`](../pipeline.mjs)) — ровно потому, что под ним спавн Rust-бинаря на вызов.

**Стоимость известна и измеряется.** `efficiencyMetrics` ([`lib/cost.mjs:81`](../lib/cost.mjs))
даёт `tokens_per_finding | tokens_per_inline | tokens_per_blocker`; `plan.chunkPlan[]`
([`pipeline.mjs:552`](../pipeline.mjs)) — `diff_chars` / `context_chars` / `windowed_paths`
на чанк. Знаменатель, по которому судят экономию, — находки, доехавшие до человека.

**Стабильность набора между прогонами одного PR — 0.08–0.2** ([RFC 04](04-token-economy.md)).
Внимание сегодня не воспроизводится: его каждый раз заново сэмплирует модель.

**Имя `triage` занято**: [`lib/triage.mjs`](../lib/triage.mjs) — авто-резолв тредов ревью.
Новый слой называется признаками (`cues`) и нарядами (`brief`).

## Предложение

### Контракты

Два чистых модуля, JS-only (как `lib/context-window.mjs` и `lib/incremental.mjs`), без I/O,
без синглтона профиля, вне `npm run check:parity`:

```js
// lib/cues.mjs
export function collectSpans(sections);      // Map<path, sectionText> → Span[]
export function collectCues(spans, facts);   // facts: { fileClass, sensitive, addedPaths,
                                             //          prescan, blast, priorPaths, weights, factors }
export function rankSpans(spans, { effortExponent });

// lib/brief.mjs
export function buildBriefs(ranked, { baseMargin, minMargin, maxMargin, budget, fileClass, sensitive });
export function rolesForHypotheses(hypotheses);
export function formatBrief(brief);
```

```js
// Cue — косвенный признак. НЕ находка: ни severity, ни confidence, в гейт не попадает.
{ key, kind: 'content'|'surface', weight?, factor?, evidence, hypotheses: string[] }

// Brief — наряд исполнителю.
{ id, rank, file, startLine, endLine, score, density, effort,
  cues: Cue[], hypotheses: string[], roles: ('security'|'correctness'|'architecture')[],
  contextMargin: number, stakes: 'blocking'|'advisory' }
```

**Спан — хунк.** Границы уже проставлены git'ом, и это естественная единица независимо
читаемого куска (Barnett et al.). Разбор `@@` живёт внутри `lib/cues.mjs`: трогать
[`lib/diff.mjs`](../lib/diff.mjs) нельзя — он под Rust-портом и parity, а разбор стоит два
десятка строк.

### Два рода признаков, и это главное решение

**Содержание складывается, поверхность умножает:** `score = max(0, Σ weight) × Π factor`.

Разница стоила первого замера. Лексические совпадения в тестовом файле описывают код, который
тест проверяет, а не риск в самом тесте. Слагаемым штрафом это не чинится — сумма лексикона
не ограничена сверху и перебьёт любой фиксированный минус. Множитель ограничивает по
построению. Подробности и числа — в [scent-measurement.md](../docs/scent-measurement.md).

| Признак | Род | Вес / множитель | Как считается |
|---|---|---|---|
| `shape:modified` | содержание | +2 | в спане есть и `+`, и `-` |
| `shape:dense-add` | содержание | +1 | доля добавленных строк > 0.8 |
| `shape:guard-insert` | содержание | +3 | добавлены ветвление и `return`/`raise`/`throw` **в существующий** код (есть контекстные строки) |
| `lex:*` (9 классов) | содержание | +2…+3 | лексикон по `+`-строкам; класс считается один раз на спан |
| `api:exported-changed` | содержание | +2 | экспортируемый символ в добавленных строках |
| `prescan:hit` | содержание | +3 | попадание eslint/ast-grep в спан |
| `graph:caller-outside` / `graph:cross-community` | содержание | +2 / +1 | из `parseBlastDependents` |
| `prior:seen` | содержание | +2 | путь встречался в 👎-журнале или прошлых находках |
| `path:test` | поверхность | ×0.25 | тестовый путь |
| `path:docs` | поверхность | ×0.1 | класс роутера `docs`/`skip` |
| `path:config` | поверхность | ×0.6 | класс роутера `config` |
| `path:sensitive` | поверхность | ×1.5 | `profile.layout.sensitive` |
| `shape:move-symmetry` | поверхность | ×0.2 | >90% токенов `+` совпадают с `-` — перемещение, не логика |

Лексические классы и их гипотезы: `unchecked-error`, `null-deref`, `off-by-one`,
`async-race`, `resource-leak`, `injection`, `authz`, `secret`, `api-contract`.

Гипотеза → роль — таблица `HYPOTHESIS_ROLE`, а не эвристика в промпте: `injection`/`authz`/
`secret` → `security`; `unchecked-error`/`null-deref`/`off-by-one`/`async-race`/`resource-leak`
→ `correctness`; `api-contract`/`cross-boundary` → `architecture`. Пустой список гипотез —
это «нет адресной роли», а не «все роли».

Веса и множители перебиваются профилем (секция `cues`), дефолты консервативные. Базовое
ранжирование — unsupervised: `score / effort^e`, `e = 0.5` по умолчанию (выбран замером, см.
ниже, а не осторожностью).

### Этап 1 — цена (не сделано)

`windowChunkFileContents` получает margin **на файл**, а не на чанк:
`margin(file) = clamp(f(score), minMargin, 2·base)`, где `base` — сегодняшний
`REVIEW_CONTEXT_MARGIN`. Бюджет — **перераспределение, а не рост**: сумма окон по умолчанию
равна сегодняшней трате (`buildBriefs` это уже обеспечивает и покрыто тестом). Добавленный
файл окна не получает (решение 1 RFC 04), освобождённое уходит верхушке.

Инкрементальный прогон не ломается: `fileInputHashes` считается по **оконному** тексту
([`pipeline.mjs:470`](../pipeline.mjs)), файл самоинвалидируется при смене окна, править
`configFingerprint` не нужно — тот же довод, что в RFC 07.

Флаг `REVIEW_CUES` (default off). Гейт этапа: при суммарном контексте ≤ текущего location
recall не ниже 4/13, `tokens_per_inline` не растёт.

### Этап 2 — recall (не сделано)

1. Блок `## Наряд` в `user`-сообщении специалиста ([`lib/prompt.mjs:542`](../lib/prompt.mjs)):
   спаны этой роли в этом чанке, их признаки с уликами и гипотезы. Обязательная формулировка:
   **признак — повод посмотреть, а не утверждение; не подтвердилось — молчи.**
2. Подмножество ролей на чанк вместо всё-или-ничего
   ([`lib/chunk-routing.mjs:33`](../lib/chunk-routing.mjs)), fail-open «состав неизвестен →
   все роли».

Гейт этапа: location recall ≥ 7/13 при росте токенов ≤ 10% **и** по-прежнему 0 ложных
блокировок на 5 clean-контролях. Стоп-сигнал — рост `fp_filter.removed` или блокировок на
clean: значит, подсказка стала внушением.

**Побочное предсказание, самое сильное из всех.** Стабильность набора между прогонами одного
PR (сейчас 0.08–0.2) должна **вырасти**: внимание фиксируется детерминированными признаками,
а не сэмплируется моделью заново. Если сбудется — наряды не оптимизация цены, а способ
сделать ревью воспроизводимым; ни один механизм экономии из RFC 04/07 такого не обещает.

Событие `cues` в JSONL: `{ spans, briefs, scoreHistogram, rolesPerChunk, marginBefore,

Этап 0 миграции не требует: слой не подключён, гейт не изменился, артефакт экспорта не

## Риски и что не делаем

1. **Тихая потеря recall.** Ни один спан не исключается — он только теряет бюджет. Нижняя
   граница окна (`minMargin`, 8 строк) и полный дифф остаются всем. `grafana-99911` —
   документированный случай, где признаки дают ноль: пропущенное присваивание поля
   поверхностной сигнатуры не имеет.
2. **Гипотеза как внушение.** Наряд повышает шанс, что модель «найдёт» то, что ей назвали.
   Защита: наряд не создаёт находок, гейт не меняется (refutation + verifier + `confidence`
   на месте), стоп-сигналы — clean-контроли и `fp_filter.removed`.
3. **Переобучение на 13 кейсах.** Уже случилось на этапе 0 и задокументировано. Веса — в
   профиле; расширение набора — открытый пункт B6 backlog'а; независимая проверка — прогоны
   с моделями, а не то же ранжирование.
4. **Недоступность фактов.** `examples/ci/pr-review.yml:46` ставит `fetch-depth: 0`, но
   потребитель может урезать: отсутствие факта = вес 0, не ошибка. Проверено тестом.
5. **Граница structure не размывается.** Покрытие (LCOV) на этапе 1 приходит **внешним
   фактом через `deps`**; `lib/cues.mjs` не импортирует `structure-*`, гейт по-прежнему не
   знает про structure ([RFC 01](01-structure-platform-boundary.md)).

**Не делаем:** embedding-индекс репозитория (отклонён в [backlog.md](../docs/backlog.md));
обучение модели на признаках в рантайме (веса — статический JSON); изменение весов
actionability и severity; изменение маршрутов роутера; создание находок из признаков; правки
`lib/diff.mjs`.
