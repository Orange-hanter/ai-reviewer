# Changelog

## Unreleased

**Для потребителя — что меняется при обновлении пина с `v0.4.0`:**

- **Свой sticky и inline опознаются по автору, а не только по маркеру.** Список — новая
  `REVIEW_TRUSTED_AUTHORS` (по умолчанию `github-actions[bot]`; `REVIEW_FEEDBACK_TRUSTED_AUTHORS`
  — алиас). Если отчёты в вашем репозитории пишет PAT или GitHub App, задайте его логин —
  иначе первый прогон после обновления не узнает прежний sticky: создаст второй, Δ-блок
  начнётся без истории. Откат — `REVIEW_TRUSTED_AUTHORS=` (пусто: доверять любому автору).
- **Blast-radius обязателен в шаблоне CI.** `examples/ci/pr-review.yml` ставит новую
  `REVIEW_BLAST_REQUIRED=1`: если code graph не собран или graphify недоступен, ревью
  блокирует merge до LLM-вызовов и пишет причину в sticky. Скопировали шаблон, а граф не
  строите — уберите флаг или задайте `0`. Дефолт движка — `0`, без шаблона ничего не меняется.
- `graphifyy` в шаблоне CI и в `docs/model-tuning.md`: **0.9.52 → 0.9.87** (формат вывода
  `graphify affected` и строка `Built from commit` в отчёте не изменились; ключ кэша venv сменён).
- **Блок решает сама находка, а не её соседи по 3 строкам** (RFC 17). Пропадут блоки, где
  причиной в sticky стоял minor, critical с низкой confidence блокировал за счёт соседа или
  eslint-правило вне `blockRules` блокировало через соседнюю находку. В экспорте
  `consensusBlock` теперь только у блокирующей находки (форма артефакта та же).
- **Rename с правками и удалённые файлы ревьюятся** (RFC 17): раньше первый уходил в skip,
  второй был невидим роутеру. Такие PR теперь идут маршрутом full — больше LLM-вызовов.
- **Verifier проверяет блокеры сверх `REVIEW_VERIFIER_MAX` батчами** (новая
  `REVIEW_VERIFIER_BATCHES`, дефолт `3`) вместо молчаливого понижения в minor. Прежнее
  поведение — `REVIEW_VERIFIER_BATCHES=1`.
- **Сбой verifier'а — одно состояние «недоступен»** (RFC 18). Раньше упавший HTTP-вызов
  блокировал merge по слову агрегатора, а пустой ответ модели молча пропускал. Теперь находка
  уровня блока без вердикта из-за сбоя показывается как minor с пометкой, а прогон при
  `REVIEW_LLM_REQUIRED=1` (дефолт) блокируется как degraded с баннером «verifier недоступен —
  перезапустите». Пропускать merge при сбое — `REVIEW_LLM_REQUIRED=0`; прежнее поведение
  целиком — `REVIEW_VERIFIER_STRICT=0`. Из баннера блока убрана неверная фраза «Инфра-сбои
  merge не блокируют».
- **Часть PR, упавшая у всех моделей, больше не выдаётся за отревьюенную** (RFC 19).
  Раньше результат собирался из успешных чанков молча. Теперь при `REVIEW_LLM_REQUIRED=1`
  (дефолт) — degraded-блок «ревью неполное, перезапустите», при `0` — заметка. Пропуск по
  тайм-бюджету — по-прежнему заметка.
- Формат футера sticky, namespace маркеров, контракты `swarm` / `export` / `structure` —
  без изменений.

### Исправлено — покрытие по чанкам (RFC 19)

- `engine`: `failedChunks` и `skippedChunkIndexes` в результате модели (и резервной); `demoteAll`
  сохраняет индекс чанка.
- `pipeline.mjs`: чанк покрыт, если его отревьюила хоть одна модель; `coverageGap` → degraded по
  `REVIEW_LLM_REQUIRED`; событие `coverage_gap {failed, total, paths}`, поле в событии `gate`.
- Инкрементальный state: файлы непокрытых чанков (сбой и тайм-бюджет) не получают хэш — раньше
  они считались просмотренными и не ревьюились, пока не изменятся.
- `buildSummary` (JS и Rust): вход `coverageGap`, баннер «ревью неполное» без путей файлов.

### Исправлено — сбой verifier'а (RFC 18)

- `markVerifierUnavailable` (`pipeline.mjs`): исключение первого вызова, ни одного валидного
  вердикта, тайм-бюджет и сбой хвостового батча → `verifierStatus: unavailable`, severity → minor;
  `degradedBlock` по `REVIEW_LLM_REQUIRED` в коде выхода, `wouldBlock`, событиях `gate`/`verdict`.
- `buildSummary` (JS и Rust): вход `verifierUnavailable`, заголовок «⛔ ревью не завершено», баннер;
  `verdict.blocked` и `blocked` в истории прогонов учитывают degraded-блок.
- Событие `verifier_unavailable {reason, unverified}`.
- Инкрементальный state: файл с находкой `unavailable`/`overflow` не получает хэш, находка не
  переносится — перезапуск ревьюит файл заново, а не переносит непроверенное как minor.

### Исправлено — дыры гейта (RFC 17)

- `clusterFindings`/`resolveBlockers` (JS и Rust): `consensusBlock` и `confidenceBlock`
  считаются по находке; кластер даёт только счёт моделей. Блокер кластера — первая
  блокирующая находка; `pipeline.mjs` считает блокирующие кластеры по `some`.
- `dedupeAgainstPrescan`: LLM-находка снимается только prescan-находкой не ниже по severity.
- `isRenameOnlySection` (JS и Rust): убран ранний выход по `rename from`.
- `parseDiff` (JS и Rust): на `+++ /dev/null` путь из `diff --git`; `collectDeletedPaths` —
  prescan не запускается на удалённых файлах. Удаление распознаётся только по
  `deleted file mode` в заголовке секции; внутри хунка `+++`/`---` — содержимое: строка
  `++ /dev/null` в комментарии больше не выводит файл из prescan и не обрывает разбор файла.
- `runVerifierStage`: батчи по `REVIEW_VERIFIER_MAX`, одно применение вердиктов со сдвигом
  `candidateIndex`; сбой хвостового батча сохраняет проверенное. `stats.batches` в событии `verifier`.
- Фикстуры `gate-neighbour-minor-not-blocker`, `gate-neighbour-confidence-no-lift`,
  `gate-eslint-nonblock-via-neighbour` (eval: 20 seed-кейсов); parity-кейсы `rfc17 *`.

### Добавлено — `REVIEW_BLAST_REQUIRED` (RFC 16)

Fail-closed для blast-radius по образцу `REVIEW_LLM_REQUIRED`. `blastUnavailableReason`
(`lib/graphify.mjs`) отличает инфра-сбой (`graph_missing`, `graph_unreadable`,
`graphify_unavailable|timeout|error` на всех символах) от честного «зависимых нет»;
пайплайн проверяет его сразу после blast-стадии и выходит с `1`, не тратя токены.
В observability — событие `blast_failed`. Флаг есть и в Rust-конфиге (parity).

### Добавлено — пиктограммы в PR-комментариях

`REVIEW_ICON_BASE_URL` (по умолчанию пусто — эмодзи, как раньше): sticky, шапка review-сводки и inline показывают
SVG-набор из `.github/icons/` вместо эмодзи. Набор опубликован в публичном
[Orange-hanter/ai-reviewer-icons](https://github.com/Orange-hanter/ai-reviewer-icons) — движок
приватный, а GitHub грузит картинки комментариев через прокси без авторизации. Подмена —
на границе публикации (`lib/icons.mjs`, обёртка github-клиента): HTML-комментарии с футером,
код, ответы auto-triage, логи и Telegram не меняются; эмодзи остаётся в `alt`.

### Исправлено — поддельный sticky

`readPriorStickyData`, `upsertSticky`, `readStickyReview` и `deleteStaleInline` брали последний
комментарий с маркером, не проверяя автора. Любой, кто может комментировать PR, писал
комментарий с маркером и своим футером: его «находки» уходили в промпт агрегатора как
прошлые (prompt injection) и в Δ-блок, а следующий прогон перезаписывал этот комментарий
отчётом, оставляя свой sticky устаревшим. Теперь комментарий с маркером от недоверенного
автора пропускается с записью в лог. Примитив доверенного автора переехал в `lib/util.mjs`
(реэкспорт из `lib/feedback.mjs` сохранён), конфиг — `cfg.github.trustedAuthors` (JS и Rust).

### Исправлено — текст модели ломал разметку sticky

В секциях «Замечания вне строк диффа» и «Отфильтровано как известные FP» заголовок, тело,
путь и имя модели шли в Markdown как есть: `**`, ссылки и `</details>` из ответа модели
ломали отчёт. Заголовок и модель экранируются (как уже было в Δ-блоке), в теле гасится `<`,
из пути убираются backticks. JS и Rust.

### Gold

`fp-noise-no-real-blockers` переразмечен `fp` → `tp`: находка про sticky без проверки
автора, по которой кейс «ложно» блокировался, была настоящей. Теперь кейс ждёт блок по ней
и проверяет, что старые FP PR #477 не всплывают.

### Исправлено — symlink наружу при чтении файлов PR

`readChangedFiles` проверял «файл внутри репозитория» через `resolve` без `realpath`:
изменённый в PR symlink, указывающий за пределы checkout, отдавал внешней модели содержимое
своей цели. Проверка теперь идёт через `resolveContainedPath` (realpath корня и цели), как
у карточек символов и MCP. Добавленные в PR пути не читались и раньше — их содержимое и так
приходит диффом.

## 0.4.0 — карточки символов (RFC 14), ревью-MCP и Cursor Plugin (RFC 08–12), косвенные признаки (RFC 15) — 2026-10-09

**Для потребителя — что меняется при обновлении пина с `v0.3.0`:**

- **Карточки символов включены по умолчанию** (`REVIEW_SYMBOL_CARDS=1`). Нужен граф Graphify
  (`.graphify/graphify-out/graph.json`, как для blast-radius); без него карточек нет и
  поведение прежнее. Включённая фича входит в отпечаток конфигурации инкрементального
  прогона — **первый прогон после обновления полный**. Откат — `REVIEW_SYMBOL_CARDS=0`.
- **Запасная модель** по умолчанию — `deepseek-v4.1-flash`: прежнюю `deepseek-v4-flash`
  провайдер снял. Если в вашем workflow явно прописано
  `OLLAMA_MODELS_FALLBACK: deepseek-v4-flash` (шаблон `examples/ci/pr-review.yml` это
  делал) — заменить.
- Формат футера sticky, namespace маркеров, контракты `swarm` / `export` / `structure` —
  без изменений.

### Исправлено — запасная модель снята провайдером

`OLLAMA_MODELS_FALLBACK` по умолчанию: `deepseek-v4-flash` → `deepseek-v4.1-flash`. Старую
модель Ollama Cloud снял 2026-09-25 (`410 retired`): при отказе основных моделей (например,
исчерпанном лимите) прогон уходил на неё и терял все вызовы. **Для потребителя:** если в
workflow явно прописан `OLLAMA_MODELS_FALLBACK: deepseek-v4-flash` (шаблон
`examples/ci/pr-review.yml` его прописывал) — заменить там тоже. Verifier не менялся.

### Изменено — карточки символов, второй круг аудита ([аудит RFC 14](docs/dev/audit/2026-10-09-rfc-14-symbol-cards.md))

- Символ ищется в модуле, который импортирует вызывающий файл, — а не по уникальности имени
  во всём графе; работают вызовы `ns.fn(` для `import * as ns`.
- Сигнатуры TS: дженерики, литералы типа и `=>` в аннотации не обрывают заголовок,
  перегрузки — одной карточкой, класс — с `constructor(…)`.
- Вызовы ищутся по маске всего файла: текст многострочных литералов и комментариев больше
  не даёт ложных карточек.
- Сбой графа в CI больше не заставляет заново ревьюить все файлы PR (вход карточек берётся
  из прошлого прогона, кроме файлов, чьи карточки указывают на файлы PR, и не больше одного
  прогона подряд).
- Новое: `REVIEW_VERIFIER_SYMBOL_CARDS` (по умолчанию выключено) — карточки во входе
  verifier'а; `pr-review-symbol-cards-probe` — офлайн-пробник отбора по истории репозитория.

### Исправлено — карточки символов по аудиту ([аудит RFC 14](docs/dev/audit/2026-10-09-rfc-14-symbol-cards.md))

- Устаревший Rust-бинарь `config` больше не выключает новые ключи молча: недостающие берутся
  из JS, в лог — `AiReviewerStaleBinary` со списком. Касается любого будущего ключа конфига.
- Карточка не выдаётся, если строка графа не объявляет имя, если узел — из тестов/моков, если
  имя связано в самом вызывающем файле (параметр, деструктуризация) или неоднозначно хотя бы
  по одной форме (`name` / `name()`). Объявление метода в диффе не считается вызовом.
- Граф, построенный от `layout.appDir`, больше не обнуляет карточки.
- Новое событие наблюдаемости `symbol_cards_outcome`: связь находок с карточками и датчик
  утверждений «символ не определён» по телам находок.

### Добавлено — карточки символов ([RFC 14](proposals/14-symbol-cards.md))

`REVIEW_SYMBOL_CARDS` (по умолчанию включено): для имён, которые вызывают добавленные строки JS/TS-файлов и чьё
объявление модель не видит ни в диффе, ни в окне контекста, в промпт advisors и жюри идёт
строка объявления с диапазоном — место из графа Graphify, текст из файла. Без `graph.json`
карточек нет. **Для потребителя:** включённая фича входит в отпечаток конфигурации
инкрементального прогона, поэтому первый прогон после обновления — полный. Откат —
`REVIEW_SYMBOL_CARDS=0`: промпт, хэши и отпечаток как до RFC 14. Лимиты —
`REVIEW_SYMBOL_CARDS_MAX`, `REVIEW_SYMBOL_CARDS_MAX_CHARS`; короткие тела
(`REVIEW_SYMBOL_CARDS_BODY_MAX_LINES`) выключены — не замерялись.

Основание включения — gold A/B на 9 кейсах: несовпадений с разметкой 6 → 4, стоп-кейсы
без регрессий, вход −0,5 %; по одному прогону на конфигурацию — вреда не найдено, польза
не доказана.

Шаг 1 RFC (FP-фильтр «символа нет» по графу) отменён по замеру: на 208 заголовках находок
такой класс не встретился.

### Добавлено — слой косвенных признаков и наряды, shadow ([RFC 15](proposals/15-cue-driven-briefs.md))

`lib/cues.mjs` и `lib/brief.mjs` — детерминированный слой, который по одному лишь диффу
ранжирует спаны изменений и выписывает **наряды**: где смотреть, какая гипотеза, сколько
контекста приложить, какая роль исполняет. Ни одного вызова LLM, ни одного чтения тела файла.

**Пайплайн их не импортирует — поведение гейта не изменилось ни на байт.** Это этап 0:
проверка гипотезы до того, как трогать merge-гейт.

Замер `node bin/pr-review-scout.mjs --gold-dir gold-public` (13 tp-кейсов, 22 размеченные
локации, 0 вызовов моделей): ACC@20%LOC **31,8% против 13,6%** у порядка диффа (то самое
равномерное внимание, с которым движок работает сегодня), IFA **0** против 1, P_opt **0,840**
против 0,563. Признаки переносятся между Python, TypeScript и Ruby без правил под путь.

Отчёт со всеми оговорками — [docs/scent-measurement.md](docs/scent-measurement.md), включая
две, которые нельзя пропускать: базовая линия «брать самые крупные хунки» обгоняет признаки
по Recall@3 (86,4% против 68,2%) ценой чтения на 11 п.п. большего объёма, а три правки слоя
сделаны после просмотра данных на наборе из 13 кейсов.

Ключевое решение слоя: **признаки содержания складываются, признаки поверхности умножают**
(`score = max(0, Σ weight) × Π factor`). Первая редакция со слагаемым штрафом за тестовый
путь провалила замер — лексикон в тестовых файлах вытеснял исходники, где и лежали дефекты.

Новая команда `npm run scout` (в `npm run check` не входит: первый прогон тянет диффы по сети).

### Добавлено — Rust-порт `export`/`metrics` (фаза 3.6)

Сборка артефакта экспорта (JSON/SARIF/swarm) и метрик прогона портирована в Rust
(`rust/src/export.rs`, `rust/src/metrics.rs`) под parity-тестами; `lib/export.mjs` и
`lib/metrics.mjs` — обёртки с откатом на JS, как у остальных модулей. Коммит `413273d` вошёл
в `main` мержем после тега v0.3.0, хотя раньше был записан в секцию 0.3.0.

### Добавлено — долгий MoA в IDE ([RFC 12](proposals/12-mcp-long-run.md))

`review_run` принимает `wait` (default `true`). `wait: false` сразу отдаёт stub с `jobId`;
sidecar пишется до LLM. `review_findings` / `review_artifact` принимают `jobId`; пока
`status: running` — пустые findings, не ошибка. Git-шаблон плагина больше не использует
`./bin` от cwd окна.

### Добавлено — холодный старт MCP ([RFC 10](proposals/10-mcp-cold-start.md))

Лаунчер плагина сам находит клон (`.engine-root` / cwd / `AI_REVIEWER_ROOT`). `install-local.sh`
копирует плагин, пишет якорь и **абсолютный** путь лаунчера (cwd plugin MCP у Cursor — чужое
окно, не каталог плагина). Handshake (`initialize` / `tools/list`) не импортирует пайплайн.
`variables.required` пустой — Cursor не показывает Authenticate на stdio.

### Добавлено — Cursor Plugin и агентные стадии ревью-MCP ([RFC 09](proposals/09-cursor-plugin-mcp.md))

Дешёвый контур без LLM: `review_route`, `review_prescan`, `fp_check`, `fingerprint_check`,
`review_artifact`. `review_findings` читает sidecar на диске. Живой дифф сверяет `headSha`
с `git rev-parse HEAD` (грязное дерево — `uncommitted: true`). За `REVIEW_MCP_EXTRA=1` —
`blast_scope`, `actionability_explain`, `review_metrics`.

Cursor Plugin: каталог `cursor-plugin/` (два MCP, slash-команды, skill, rule). Не гейт;
движок в плагин не входит. Local install: `cursor-plugin/README.md`.

### Добавлено — MCP полного прогона для агента ([RFC 08](proposals/08-review-mcp.md))

Отдельный stdio-сервер `pr-review-mcp`: тулзы `review_run` (полный MoA, пин `headSha`) и
`review_findings` (страница того же прогона). GitHub не пишется. В ответе `previewWouldBlock`,
не `wouldBlock` сворма — merge по-прежнему только `exit 1` в CI. Корень чтения —
`REVIEW_MCP_ROOT` (не `STRUCTURE_MCP_ROOT`). Транспорт `Content-Length` вынесен в
`lib/mcp-stdio.mjs` и общий с structure MCP.

Пайплайн: `runDetailed()` отдаёт артефакт из памяти; `--head-sha` / `cli.headSha` заполняет
пин на file-diff; dry-run summary больше не идёт в сырой `console.log` (иначе ломает кадры MCP).

### Исправлено

- **«Файла/модуля нет» о файле, который есть в репозитории, но не в PR.** Модель видела
  импорт файла вне диффа и заявляла, что его не существует; защиты семейств 1/6 знают только
  изменённые пути и такой случай пропускали. FP-фильтр теперь сверяет утверждение об
  отсутствии с деревом репозитория (`git ls-files` рабочего каталога, `deps.repoFiles`) и
  снимает находку, если путь в дереве есть ([lib/absent-path.mjs](lib/absent-path.mjs),
  семейство 7 в [docs/false-positives.md](docs/false-positives.md)). Отсутствие как условие
  рантайма («если файл не существует…») и отсутствие символа в существующем файле не
  снимаются. Дерево не читается или явно чужое (меньше половины путей PR в нём нет) —
  фильтр выключен, гейт ведёт себя как раньше.

### Добавлено — окна контекста для advisors и жюри ([RFC 07](proposals/07-windowed-file-context.md))

В промпт советников и жюри едут окна ±`REVIEW_CONTEXT_MARGIN` (по умолчанию 40) вокруг
изменённых строк файла, а не файл целиком; файл короче `REVIEW_CONTEXT_WINDOW_MIN_CHARS`
(8000) прикладывается полностью — там усечение не экономит ничего, а риск берёт целиком.
Замер на `pr-6.patch` без LLM: контекст 107 455 → **64 090** символов (−40,4%), −9,4% всего
входа прогона при неизменной нарезке.

Размер контекста и текст промптов изменены **одним** решением: заголовки ролей, схема жюри и
абзац «CONTEXT AND NO OPEN QUESTIONS» больше не обещают полный файл, маркер пропуска явно
значит «здесь не показано», а не «не существует», в карте PR появилась метка
`[THIS PART, CONTEXT WINDOWED]`. Заодно исправлена инструкция verifier'а: она обещала полный
файл с тех пор, как ему отгрузили окна, то есть лгала уже до этого изменения.

Откат — `REVIEW_CONTEXT_MARGIN=0`, поведение становится побайтово прежним.

### Добавлено — Rust-ядро под тем же публичным API

Горячие и чистые части движка портированы в Rust (`rust/`, фазы 0–3.5):

`engine`, `specialists`, `prompt`, `verifier`, `github`, `report`.

Контракт для потребителя не изменился: `lib/*.mjs` — тонкие обёртки с прежними экспортами и
прежней синхронностью. Правила деградации:

- бинаря нет (чистый клон до `cargo build`) → работает эталонная JS-копия;
- бинарь есть, но упал → ошибка пробрасывается, подмены реализации не происходит: молчаливый
  откат на JS скрывал бы регрессии;
- `AI_REVIEWER_<MODULE>_FORCE_JS=1` — принудительно JS (паритетные прогоны, отладка);
- `lib/llm.mjs` дополнительно уходит в JS, когда перехвачен `globalThis.fetch`: DI-моки тестов
  и потребителей подменяют именно его, и Rust-бинарь этой подмены не видит.

Паритет сторон проверяется `rust/parity/*.parity.mjs` (побайтовое сравнение выходов) и
`cargo test`; `test/rust-parity-guard.test.mjs` ловит по исходникам правки, внесённые только в
одну сторону, — такие расхождения не падают и не конфликтуют, а просто дают разное поведение
на машине с собранным бинарём и без него.

### Добавлено — два режима под флагом

- **Инкрементальный прогон** `REVIEW_INCREMENTAL=1` ([RFC 05](proposals/05-incremental-review.md)):
  файлы, чей **вход для модели** (секция диффа + приложенный контекст) не изменился с прошлого
  прогона, заново не ревьюятся — их находки переносятся вместе с вердиктами жюри и verifier.
  Единица сравнения — вход, а не коммит: перебазирование меняет SHA, не меняя входа, и наоборот.
  Если не изменилось ничего — **ноль вызовов LLM**.

  Перенос выполняется ПОСЛЕ refutation и verifier: иначе strict-refutation понижала бы
  подтверждённый блокер до `minor` только потому, что в этом прогоне жюри по нему не
  высказывалось — гейт молча слабел бы с каждым push. Находка по изменившемуся файлу не
  переносится никогда. Прогон принудительно полный при смене конфигурации (модели, роли,
  гейт, порог маршрута/допуска verifier, таймаут LLM) и каждый
  `REVIEW_INCREMENTAL_FULL_EVERY`-й раз. В CI состояние требует `actions/cache` на
  `.ai-review/incremental/`; без него поведение прежнее.
- **Раскладка под префиксный кэш** `REVIEW_PROMPT_LAYOUT=shared-prefix` (RFC 04, решение 5):
  `[system: общая рамка] [user: контекст чанка] [user: инструкция роли]` — первые два
  сообщения побайтово равны у всех ролей чанка, и провайдер может отдать их из кэша. Раньше
  роль лежала в `system`, и четыре вызова по чанку расходились с первого токена.

  Новый пробник `pr-review-probe-cache` замерил, даёт ли провайдер такую скидку. **На Ollama
  Cloud не даёт** (`kimi-k2.7-code`, `minimax-m3`: повтор префикса не быстрее контроля, кэш в
  `usage` не сообщается) — поэтому дефолт `legacy` подтверждён замером, а не осторожностью, и
  раскладка ждёт провайдера с префиксным кэшем

### Добавлено — измеримость расхода

- `llm_call` несёт токены **для всех ролей** (специалисты писали только `text_chars`) и

  важнее регистронезависимого, неоднозначный кандидат не сливается вовсе и попадает в
  `warnings`, а из набора выбывает ровно слитая сущность — не все делящие с ней ключ
- **`validateStructureFacts` не проверял ссылочную целостность**: битые `from`/`to` рёбер и
  `entityRef`/`targetRef` контрактов уезжали потребителю молча — валидатор смотрел только на
  массивы, лимиты, пути и fingerprint. Добавлена проверка: ссылка на неизвестную сущность
  теперь отклоняется
- **LCOV приписывал одноимённым функциям чужие хиты.** `FNDA` адресует функцию только по
  имени, а `FN` может объявить это имя в файле дважды (вложенные функции в разных областях —
  обычный JS): обе записи получали один счётчик, непокрытая функция объявлялась `covered` с
  чужими хитами вопреки собственному `DA` той же строки, и файл рапортовал полное покрытие
  функций. Теперь счётчик привязывается по порядку записей — istanbul пишет `FN` и `FNDA`,
  обходя один и тот же `fnMap`, поэтому N-я `FNDA` относится к N-й одноимённой `FN`. Такая
  привязка помечается `attribution: 'order'` и не претендует на `exact`: она опирается на
  поведение писателя, а не на ключ формата. Если числа записей разошлись (типично после
  слияния отчётов, где `FNDA` схлопнуты по имени), привязывать нечего — `hits: null`,
  observation со `status: unresolved` и `confidence: ambiguous`, имя в `warnings`, а
  знаменатель доли считается только по функциям с однозначным ответом
- **MCP-сервер не соблюдал собственный `inputSchema`.** Схема объявлена в `tools/list`, но
  аргументы не проверялись: `dependencyDepth` и размер ответа ограничены внутренними
  потолками `buildStructureContext`, а длина `scopeRefs`/`contractRefs` — ничем, при том что
  `matchesScope` перебирает список на каждую сущность. Границы теперь берутся из самой схемы,
  чтобы код и объявленный контракт не разъезжались
- **Страж varint в SCIP смотрел на сдвиг, а не на величину.** Varint, завершившийся на сдвиге
  49, мог выйти за 2^53: число теряло точность, портились низкие биты, и разбор падал с
  ложным диагнозом «truncated» — ошибка указывала не туда, где сломалось. Проверяется сама
  величина через `Number.isSafeInteger`
- **Граница «слой» строилась из имени файла.** `boundaryCandidates` брал второй сегмент пути
  под `appDir`, не проверяя, что за ним есть третий: `src/index.ts` превращался в границу
  `layer:index.ts`. На реальном графе (13437 узлов, `appDir: tools`) это давало 11
  выдуманных «слоёв» — `audit-all.mjs`, `package.json`, `vite.config.ts` и подобные, — и
  границ становилось 28 вместо 18. Слой теперь требует третьего сегмента. Заодно снят
  `else if`: путь под `appDir`, чей слой не заявлен в `layerDirs`, раньше не попадал ни в
  слой, ни в модуль и молча оседал в `boundary:repository` — теперь у него остаётся модуль.
  Границы влияют на `crossBoundary`, а значит на `dependencyRisk` и подсказки, поэтому у
  существующих репозиториев сместится `facts.fingerprint` — это работа фикса, не регрессия
- **Продюсер мог выдать факты, которые отвергает его собственная схема.** Сущности и рёбра
  ограничены потолками, а контракты — нет, хотя `structure-facts.v1.schema.json` объявляет
  `contracts: maxItems 5000`: на 5200 callable-узлах получалось 5079 контрактов. Появился
  потолок с предупреждением `contracts truncated at N`, и при обрезке первыми уходят
  эвристические `entrypoint` — доказанные `implements`/`inherits` остаются. `maxEntities` и
  `maxEdges` теперь клампятся к потолкам схемы: env-переменная не должна уметь сделать вывод
  невалидным. `validateStructureFacts` проверяет `contracts` и `boundaries` — раньше их не
  проверял никто
- **Метка god-узла помечала однофамильцев во всех файлах.** Сопоставление шло по
  `label.toLowerCase()` без пути, поэтому одна запись в `.graphify_analysis.json` помечала и
  `handler()` из `src/a.ts`, и `Handler()` из `src/b.ts`. Тот же класс дефекта, что в слиянии
  SCIP и в `FNDA`. Запись с `id` или `source_file` адресует узел точно; голое имя, которое
  разрешается больше чем в одну сущность, не помечает ничего и уходит в `warnings`
- **Узлы исчезали из фактов бесследно.** `normalizeRepoPath` бросает на небезопасном
  `source_file`, и `catch { continue }` глотал такой узел молча — по выходу нельзя было
  понять, целиком ли разобран граф. Отброшенные узлы и неразобранные `source_location`
  теперь считаются и попадают в `warnings`
- **Сгенерированный markdown врал о своей полноте.** `buildStructureMarkdown` режет подсказки
  на 50, сценарии на 200, хотспоты на 100 и не говорил об этом ни слова, тогда как блок
  «Data quality» в том же документе рапортовал `Truncated: no`. На реальном прогоне это 50
  показанных подсказок из 679 и 100 хотспотов из 678. Документ теперь называет, сколько
  строк он опустил
- **Значения из репозитория ломали разметку документа.** `esc` экранировал `|` и перевод
  строки, но не обратную кавычку, а `ruleId` и `remediation` не экранировались вовсе:
  перевод строки в `remediation` создавал заголовок, кавычка в пути рвала code span. Путь
  реальный — `remediation` подставляет `obligationRef` из obligations cod-doc. Значения в
  code span оборачиваются оградой длиннее самой длинной серии кавычек внутри, остальное
  проходит через `esc`
- **Упрочнение без живого дефекта** (проверено на реальном выводе Graphify, 13437 узлов и
  22097 рёбер): одинаковые рёбра дедуплицируются перед сортировкой — раньше дубль удваивал
  `fanIn`, потому что `assessDependencyRisk` считает по длине списка; в первом цикле
  контрактов появилась защита от повторного ключа, которая была только во втором; номер
  строки берётся до хвостовой колонки (`src/a.ts:10:5` → 10, а не 5) и понимается форма
  `#L10`. На этом производителе ни дублей рёбер, ни таких форм `source_location` нет —
  Graphify пишет только `L<n>`, — поэтому это защита от чужого формата, а не исправление
  наблюдаемой поломки

## 0.2.0 — вынос движка в самостоятельное решение


Первый релиз, в котором пакет не привязан к конкретному репозиторию. Движок синхронизирован
с рабочей версией потребителя (август 2026) и расцеплен с ней через профиль проекта.

### Добавлено

- **Профиль проекта** (`lib/profile.mjs`, [docs/profiles.md](docs/profiles.md)): маркеры
  комментариев, правила репозитория для промпта, раскладка каталогов для prescan, scope и
  allowlist ast-grep правил, пути feedback/observability/export — в одном JSON у потребителя.
  Источник: `REVIEW_PROFILE` → явное назначение → `.ai-reviewer.json` в корне → нейтральный
  дефолт. Битый профиль не роняет ревью (fail-open + строка в лог).
- **Маршрут находки по доказуемости** (`lib/actionability.mjs`): inline или свод решает сумма
  детерминированных сигналов (prescan, verifier, повтор, консенсус, чувствительная зона),
  а не ярлык severity. Пороги — `REVIEW_ACTIONABILITY_MIN`, `REVIEW_MAX_ADVISORY_INLINE`.
- **Δ-блок и история прогонов в sticky**: что появилось и что ушло с прошлого прогона;
  отпечаток кода у перенесённой находки (точный фикс снимает находку).
- **Метрики прогонов** (`lib/metrics.mjs`, `pr-review-metrics`): сводка по observability-логу.
- **Gold-набор** (`gold/`, `pr-review-gold`): shadow-прогон полного пайплайна с LLM на
  размеченных TP/FP диффах.
- Новые CLI: `pr-review-metrics`, `pr-review-gold`, `pr-review-probe-models`.
- Шаблоны workflow потребителя — [`examples/ci/`](examples/ci/) (ревью, harvest, promote, метрики),
  все на пиновом чекауте движка вместо копирования кода из базовой ветки.
- `test/profile.test.mjs` — поведение нейтрального профиля и загрузка чужого.

  `<!-- ai-review -->`, SARIF `ai-review/<severity>`, файлы экспорта `ai-review.json` /
